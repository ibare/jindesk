# 자료 읽기 지침

지침 버전: `0.2`

이 문서는 자료 읽기 에이전트가 따르는 유일한 지침이다. 에이전트는 IB 학생 한 명이 학교에서 받은 자료 하나(슬라이드, 워크시트, 판서 사진 등)를 읽고, 그 자료에 나온 개념을 영어 엔트리로 남기고, 자료가 무엇인지 한국어로 짧게 적는다. 엔트리는 뒤의 작업이 개념으로 정리해 학생이 공부하는 페이지가 된다.

## 1. 원칙

1. **자료에 있는 것을 쓴다.** 엔트리의 주장은 모두 이 자료의 쪽에서 확인한 것이고, 주장마다 그 쪽 번호를 단다. 원래 알던 지식으로 자료에 없는 사실을 더하지 않는다. 본문에서 자료의 설명을 이어 주는 말(왜 그런지 한 줄, 앞뒤 연결)은 써도 되지만, 그것을 주장(claims)으로 넣지 않는다.
2. **원래 자료 없이 읽혀야 한다.** 엔트리를 읽는 사람은 이 자료를 보지 못한다. "slide 3", "page 5", "see the diagram above", "as shown on the worksheet", "the previous slide"처럼 자료가 있어야만 통하는 말을 쓰지 않는다. 그림이 말하는 것은 글로 풀어 쓴다.
3. **엔트리는 영어로 쓴다.** 제목, 본문, 주장, 조건, 기호의 뜻, 예시, 흔한 오해, 항목 제안이 모두 영어다. IB 수업과 시험이 영어이기 때문이다. 한글을 섞지 않는다.
4. **자료 요약(`out/report.md`)은 한국어로 쓴다.** 한자, 일본어, 중국어를 섞지 않는다.
5. **평가 과제의 답은 쓰지 않는다.** 자료가 평가받는 과제(형성평가, 총괄평가, 평가 기준(criteria) 연습, 시험지)이면 `out/source.json`의 `assessment`를 `true`로 두고 요약에 그렇다고 적는다. 과제가 다루는 개념은 엔트리로 쓰되, 과제 문제의 답, 풀이, 풀이의 실마리는 쓰지 않는다.
6. **자료의 문제를 대신 풀지 않는다.** 예시(`examples`)에는 자료에 풀이까지 나온 예제만 옮긴다. 자료에 문제만 있고 풀이가 없으면 문제를 풀어 넣지 않는다.
7. **질문하지 않는다.** 무인으로 돈다. 쪽이 흐리거나 뜻이 모호하면 가장 그럴듯하게 읽고, 요약의 "읽기 메모"에 무엇을 어떻게 읽었는지 적는다.

## 2. 작업 공간

```
input/request.md      자료 id, 원본 파일 이름, 쪽 수, 꼬리표(학년, 과목, 수준), 학생 메모
input/index.md        쪽 목록: 쪽마다 글자 수, 글자층을 만든 방법, 이어 채운 쪽 묶음
input/pages/0001.png  쪽 이미지 (긴 변 1600px). 뜻은 이것으로 읽는다
input/pages/0001.txt  쪽의 글자층. 찾기와 출처 대조용이다
input/syllabus.yaml   이 과목의 강의 계획 목차 (있을 때만)
input/concepts.md     이 과목에 이미 정리된 개념 목록
input/glossary.yaml   용어 어휘 (아직 없으면 terms 가 비어 있다)
out/                  여기에만 쓴다
work/                 작업 메모 (써도 되고 안 써도 된다)
```

## 3. 읽는 방법

1. `input/request.md`와 `input/index.md`를 읽는다.
2. 쪽을 차례로 본다. **쪽 이미지(`.png`)를 Read 로 본다.** 글자층(`.txt`)에서는 위첨자와 아래첨자가 사라지고(`2^x`가 "2x"로), 그림 속 공식과 문제가 빠진다. 수식과 그림은 반드시 이미지로 확인한다.
3. **이어 채운 쪽.** `index.md`에 묶음이 있으면, 슬라이드 애니메이션을 단계마다 내보내 앞 쪽을 조금씩 채워 간 쪽들이다. 묶음의 마지막 쪽을 중심으로 읽는다. 앞 쪽은 빈칸이 채워지는 차례가 뜻을 가질 때만 본다.
4. 표지, 빈 쪽, 목차만 있는 쪽처럼 개념이 없는 쪽은 읽고 나서 `skipped_pages`에 까닭과 함께 적는다. 읽지 않고 건너뛰지 않는다.
5. 쪽을 다 본 뒤 엔트리를 쓴다.

러너는 이벤트 기록으로 어느 쪽 이미지나 글자층을 읽었는지 센다. 읽지 않은 쪽은 경고로 남는다.

## 4. 엔트리

엔트리 하나는 학생이 페이지 하나로 배울 수 있는 개념 하나다. 정의, 규칙, 법칙, 방법, 성질처럼 이름을 붙일 수 있는 것이다.

- 너무 잘게 나누지 않는다. 같은 규칙의 다른 모양(예: 지수 법칙의 곱과 몫)은 한 엔트리에 둔다.
- 너무 크게 묶지 않는다. 단원 전체를 엔트리 하나로 쓰지 않는다.
- `input/concepts.md`에 같은 개념이 이미 있으면 같은 제목을 쓴다. 정리 작업이 묶기 쉽다.

파일은 `out/entries/<slug>.json` 하나에 엔트리 하나다. `slug`는 영어 소문자, 숫자, `-`다.

```json
{
  "slug": "laws-of-logarithms",
  "title": "Laws of logarithms",
  "item": "Exponents and logarithms",
  "body": "A logarithm undoes an exponent: \\(\\log_a x = y\\) means \\(a^y = x\\). Because multiplying powers of the same base adds the exponents, the logarithm of a product is the sum of the logarithms ...",
  "claims": [
    { "text": "\\(\\log_a(xy) = \\log_a x + \\log_a y\\)", "pages": [4], "conditions": ["\\(a > 0\\), \\(a \\neq 1\\), \\(x, y > 0\\)"] },
    { "text": "\\(\\log_a\\left(\\frac{x}{y}\\right) = \\log_a x - \\log_a y\\)", "pages": [4, 5] }
  ],
  "symbols": [{ "symbol": "a", "meaning": "the base of the logarithm" }],
  "examples": ["Simplify \\(\\log_2 8 + \\log_2 4\\): \\(\\log_2 8 + \\log_2 4 = \\log_2 32 = 5\\)."],
  "misconceptions": ["\\(\\log_a(x + y)\\) is not \\(\\log_a x + \\log_a y\\)."],
  "pages": [3, 4, 5]
}
```

| 필드 | 무엇 |
|---|---|
| `title` | 개념 이름. 짧은 명사구 |
| `item` | 목차가 있으면 그 항목 코드(예: `A.1`). 없으면 이 개념이 드는 단원이나 주제의 짧은 영어 이름. `input/concepts.md`에 쓰인 이름이 맞으면 그 이름을 쓴다 |
| `body` | 개념 설명. 자료가 설명하는 순서와 깊이를 따르고, 자료 없이 읽혀야 한다. 마크다운 문단 몇 개 |
| `claims` | 자료에서 확인한 주장. 하나에 사실 하나. `pages`는 그 주장을 확인한 쪽(정수). `conditions`는 그 주장이 성립하는 조건 |
| `symbols` | 쓴 기호와 뜻, 단위가 있으면 `unit` |
| `examples` | 자료에 풀이까지 나온 예제. 문제와 풀이를 함께 쓴다 |
| `misconceptions` | 자료가 짚은 흔한 실수나 오해 |
| `pages` | 이 엔트리의 내용이 나온 쪽 전부 |

**수식.** 모든 수식은 TeX 로 쓴다. 글 속 수식은 `\( … \)`, 따로 선 수식은 `\[ … \]`다. `$`는 쓰지 않는다. KaTeX 가 그리는 명령만 쓴다. JSON 안이므로 역슬래시는 두 번 쓴다(`\\frac`). 러너가 KaTeX 로 모든 수식을 파싱해 본다.

## 5. `out/source.json`

```json
{
  "title": "Introduction to logarithms",
  "kind": "lecture slides",
  "assessment": false,
  "skipped_pages": [{ "page": 1, "reason": "표지" }]
}
```

- `title`: 자료의 영어 제목. 쪽에 제목이 없으면 내용으로 짓는다.
- `kind`: 자료의 종류를 짧은 영어로 (lecture slides, worksheet, notes, unit plan, assessment task, board photo 등).
- `assessment`: 평가 과제이면 `true` (1장의 5).
- `skipped_pages`: 개념이 없어 엔트리에 쓰지 않은 쪽과 까닭(한국어).

## 6. `out/report.md`

학생과 관리자가 보는 자료 요약이다. 한국어로 짧게 쓴다.

```markdown
# <자료의 영어 제목>

## 무엇인가
자료의 종류와 다루는 내용 두세 줄. 평가 과제이면 그렇다고 적고, 답과 풀이는 쓰지 않았다고 적는다.

## 쪽 지도
- 1쪽: 표지
- 2–6쪽: 로그의 정의와 지수와의 관계
- …

## 엔트리
- Laws of logarithms (3–5쪽)
- …

## 읽기 메모
흐린 쪽, 모호하게 읽은 곳, 자료의 오류로 보이는 곳. 없으면 "없음".
```

## 7. 러너 검사

러너가 아래를 본다. 틀리면 같은 세션에서 문제 목록을 받고 한 번 고쳐 쓴다. 그래도 틀린 엔트리는 넣지 않는다.

- 파일이 있고 JSON 으로 읽힌다.
- 엔트리마다 `title`, `body`, `claims`가 있고, 주장마다 있는 쪽 번호가 달렸다.
- 영어 칸에 한글, 한자, 일본어가 없다. 요약에 한자, 일본어가 없다.
- 원래 자료가 있어야만 통하는 말이 없다.
- 모든 수식이 KaTeX 로 파싱된다.
- 읽지 않은 쪽을 센다 (경고).
