# 결정 기록

2026-10-16 설계 대화에서 정한 것이다. 바꾸면 이 문서에 날짜와 함께 덧붙인다(지우지 않는다).

## 정한 것

### 1. Assayer 와 따로 만든다
Assayer 는 설계 검토와 PR 리뷰를 위한 앱이라 DP 과목, 강의 계획, 학습 화면을 다루는 방식이 아니다. 엔진의 실행 방식(격리된 `claude -p`, 러너가 결정적인 일을 하는 구조)만 옮겨 오고 앱은 새로 만든다.

### 2. 학생 한 명이 자기 맥에서 쓰는 Mac 앱이다
여러 사람, 배포, 계정 관리를 생각하지 않는다. 작업도 학생 맥에서 돈다. 관리자는 자기 맥에서 앱을 고치고 릴리즈한다.

### 3. 작업은 Assayer 방식으로 돈다
작업마다 격리된 작업 공간에서 `claude -p --restricted`를 띄운다. 입력 고정, 산출물 검증과 배치는 러너가 한다. 에이전트는 작업 공간을 읽고 `out/`, `work/`에만 쓴다. 웹 호출은 검사 훅을 거친다.

### 4. 강의 계획 목차는 따로 만든다
자료를 넣을 때 강의 계획 항목을 고르게 하지 않는다. 미리 있는 목록이 아니기 때문이다. "목차 만들기" 작업이 과목 가이드, 공개 과목 요약, 선생님의 과정·단원 안내에서 목차를 만들고, 처음 한 번 사람이 확인한다. 자료 읽기가 엔트리마다 항목 코드를 제안하고 러너가 목차와 대조한다. 목차에 없으면 "목차 밖"에 둔다. DP 는 학년 초에 한 번 만들고, MYP 는 단원 안내가 올 때마다 단원이 더해진다.

> 2026-10-17 자료를 넣을 때 붙이는 값은 21 을 본다.

### 5. 학습 내용은 영어가 원문이고, 한국어는 문단마다 곁에 둔다
문서 전체를 한국어로 바꾸는 전환은 두지 않는다. 읽던 자리를 잃기 때문이다. 문단 끝의 단추로 그 문단 바로 아래에 한국어를 펼친다. 같은 영어 용어는 용어 어휘로 늘 같은 한국어로 옮긴다. 앱의 메뉴와 안내 글은 한국어다.

### 6. 그림은 블록 어휘 안에서 고른다
에이전트는 스크립트를 쓰지 않고 정해 둔 블록(수식, 그래프, 실험, 회로, 분자, 반응식 등)의 명세만 쓴다. 그리는 코드는 관리자가 짜서 앱 번들에 넣는다. 러너는 명세의 주장을 계산으로 확인한다(반응식 균형, 회로 전류, 확인 문제의 답). 블록 어휘에 없는 그림 요청은 관리자에게 "새 블록 요청"으로 간다.

> 2026-10-16 바뀌었다. 18 을 본다.

### 7. 출처를 단다
설명의 주장마다 자료와 쪽을 단다. 러너가 그 쪽이 있는지, 에이전트가 실제로 읽었는지 대조한다. 출처 없는 설명은 "보충"으로 따로 보인다.

### 8. 코멘트는 단위에 붙고 세 가지다
메모(학생만 본다), 질문("물어보기" 작업이 그 개념의 페이지와 원래 자료만 보고 답한다), "이상해요"(관리자가 지침을 고칠 때 본다). 코멘트는 단위 id, 판, 인용으로 자리를 찾는다.

### 9. 부분 다시 만들기를 처음부터 고려한 구조로 둔다
페이지는 id 가 있는 단위(문단, 블록, 풀이 단계)로 이루어지고, 단위마다 판과 어디서 왔는지의 해시가 있다. 요구는 방식(더 쉽게, 더 자세히, 예시 더, 그림으로, 그림 다시, 단계 더, 고치기)을 고르고 메모를 붙인다. 요구는 데이터로 남아 나중에 페이지 전체를 다시 만들 때도 적용된다. 기능은 3단계에 만들지만, id·판·해시·요구 파일은 1단계부터 둔다.

### 10. git 을 쓰지 않는다
학생이 공부하며 git 과 GitHub 에 자료를 잇는 것은 불편하고 커밋도 문제가 된다. 모든 산출물은 데이터 폴더에 파일로 쓴다. 백업은 폴더를 통째로 한다(앱의 "백업 만들기"가 잠금을 잡고 만든다). 입력 고정은 커밋 해시 대신 내용 해시로 한다.

### 11. 데이터 폴더는 앱이 정한 전용 폴더다
기본은 홈 아래 `~/Jindesk/`이고 처음 켤 때 바꿀 수 있다. 앱 번들 안에는 두지 않는다(업데이트 때 바뀌고 서명이 깨진다). iCloud 로 동기화되는 폴더는 경고한다. 다시 만들 수 있는 것(색인, 쪽 이미지, 작업 공간)은 데이터 폴더 밖에 둬서 백업을 작게 한다.

> 대화에서는 "앱 디렉토리"라고 했다. 학생이 찾아 통째로 백업하기 쉬운 보이는 폴더로 적었다. `~/Library/Application Support` 아래로 바꾸려면 `DATA.md`의 위치 한 곳만 바꾸면 된다.

### 12. 파일이 원본이고 SQLite 는 색인이다
사람이 읽는 파일은 YAML, 덧붙이는 기록은 JSONL, 작은 기계 기록은 JSON 이다. 에이전트는 JSON 만 쓰고, YAML 은 러너가 정해진 모양으로 쓴다. 화면은 이 파일들을 그때그때 조합해 그린다. SQLite 는 검색과 목록을 위한 색인이고, 캐시 폴더에 두며 언제든 파일에서 다시 만든다. SQLite 에만 있는 데이터는 없다.

### 13. 앱은 GitHub Releases 로 자동 업데이트한다
이 리포(`ibare/jindesk`, 공개)의 Releases 에 앱과 appcast 를 올린다. Sparkle 2 를 쓰고 업데이트 파일은 EdDSA 로 서명한다. 앱은 Developer ID 로 서명하고 공증한다(유료 개발자 계정이 있다). 작업이 돌고 있으면 설치를 미룬다.

### 14. 마이그레이션은 사본에서 하고 검증한 뒤 바꿔 끼운다
데이터 폴더에 스키마 버전을 둔다. 모양 변경은 결정적인 코드로 한다(관리자가 Claude Code 로 쓰고, 학생의 백업 사본으로 시험한다). 의미 변경만 에이전트 마이그레이션 작업이 하고, 결과는 러너가 검증한다. 학생이 쓴 글(코멘트, 메모, 요구의 메모)은 에이전트에 통과시키지 않고 바이트 그대로 옮긴다. 새 지침 때문에 내용을 다시 쓰는 것은 마이그레이션이 아니라 재생성이다.

### 15. 관리자와는 보내기·가져오기 묶음으로 주고받는다
git 이 없으니 관리자가 결과를 보는 길이 따로 필요하다. 학생이 "관리자에게 보내기"로 고른 코멘트("이상해요", 질문), 관련 페이지, 실패한 작업의 실행 기록, 버전 정보를 zip 으로 내보낸다. 메모와 원본 자료는 넣지 않는다. 관리자의 답글은 "가져오기 묶음"으로 돌아온다.

> 2026-10-16 바뀌었다. 20 을 본다.

### 16. 토큰은 키체인에만 둔다
Claude 토큰은 관리자가 설치할 때 키체인에 넣는다(`SETUP.md`). `.env`는 쓰지 않는다. 데이터 폴더를 통째로 백업하므로 거기에 토큰을 두면 백업에 함께 복사되기 때문이다. 러너는 자식 프로세스에만 토큰을 넘긴다.

### 17. 평가받는 글을 대신 쓰는 작업은 두지 않는다
IA, EE, TOK 에세이처럼 평가받는 글을 대신 쓰는 작업은 만들지 않는다. 앱은 이해를 돕는 데만 쓴다.

### 18. 그림과 인터랙션은 에이전트가 코드로 짠다
2026-10-16 덧붙임. 6 을 바꾼다.

블록 어휘 방식으로는 새 그림이 필요할 때마다 관리자가 명세 스키마, 러너 검사, 렌더러를 만들어 릴리즈해야 한다. IB 과목이 넓어 그림 종류에 끝이 없으니 관리자가 렌더러를 끝없이 만들게 되고, 그동안 학생의 요구는 멈춘다. 그래서 에이전트가 개념에 맞는 그림과 인터랙션을 HTML·JS 코드로 직접 짠다. 관리자는 블록 틀과 공통 부품(테마 색, 글꼴, KaTeX, 슬라이더, 좌표축 같은 것)만 만든다.

엄밀성 검사는 글에 둔다. AI 가 만드는 내용에서 틀림을 모두 없앨 수는 없다. 글이 바르게 서 있으면 학생이 이상한 그림을 알아챌 수 있지만, 글이 이상하면 앱의 결과 전체를 믿을 수 없다. 그래서 글은 지금처럼 출처, 주장 장부, 독자 시험, 격리 검증으로 확인하고, 그림은 러너가 돌아가는지(오류 없음, 그려짐, 멈추지 않음)만 본다. 그림이 틀리면 학생이 "이상해요"나 "그림 다시"로 고친다. 그림에만 계산 검사와 판정 에이전트를 붙이는 것은 들인 품에 비해 얻는 것이 적다.

보안은 이 앱에서 무게가 크지 않다(학생 한 명이 자기 맥에서 쓴다). 그림 블록을 블록마다 iframe 에 두는 것은 한 그림이 깨지거나 멈춰도 페이지의 나머지가 살아 있게 하려는 것이다.

수식(`math`)과 풀이(`derivation`)는 글에 가까우므로 지금처럼 데이터로 두고 검사한다.

### 19. 그림 블록은 라이브러리를 가리지 않고, 만들 때 받아 둔다
2026-10-16 덧붙임.

라이브러리를 미리 골라 번들에 넣으면 그것도 제약이 되어 그림의 선택지가 좁아진다. 그래서 에이전트는 필요한 JS 라이브러리를 CDN 주소로 마음대로 불러 쓴다. 러너는 그림을 만들 때(돌아가는지 확인할 때) 그 그림이 불러간 파일을 모두 데이터 폴더에 받아 두고, 보일 때는 그 사본을 쓴다. 그래서 보는 동안에는 네트워크가 없어도 되고, CDN 의 파일이 바뀌어도 그림은 그대로다.

이 앱에서는 소프트웨어 구조의 엄밀함보다 자료의 충실도와 학습 최신성이 먼저다. 둘이 부딪치면 앞의 것을 고른다.

### 20. 보내기·가져오기 묶음을 두지 않는다
2026-10-16 덧붙임. 15 를 바꾼다.

학생과 관리자는 같이 산다. 학생이 무언가를 원격으로 보낼 까닭이 없다. 관리자가 코멘트와 기록을 볼 때는 학생 맥에서 직접 보거나 백업을 가져와 읽는다. 그 방법은 관리자가 정하고, 앱에는 기능으로 두지 않는다. 관리자 답글(`reply`)과 살펴보기 모드도 함께 뺀다.

### 21. 과목·학년·수준은 미리 등록하지 않고 자료에 꼬리표로 붙인다
2026-10-17 덧붙임.

학년 > 과목 > 수준 같은 틀을 미리 만들지 않는다. 자료를 넣을 때 그 자료가 무슨 자료인지 꼬리표(학년, 과목, 수준)로 붙인다. Assayer 의 설계안 검토에서 프로젝트를 적듯이, 이전에 쓴 값과 미리 준비한 값에서 고르거나 직접 적는다. 과목 목록은 자료들에 붙은 꼬리표에서 모아 보인다.

- 꼬리표는 열린 이름-값이다. 학년·과목·수준은 처음 제안하는 이름일 뿐이고, 나중에 다른 이름(자료 종류, 단원 등)을 더해도 구조를 고치지 않는다.
- 수준도 정해진 값이 아니다. DP 의 SL/HL 만이 아니라 MYP 수학의 Standard/Extended 같은 값도 있다.
- 자유 입력이 갈라지지 않게, 적은 값이 이미 있는 값과 대소문자·띄어쓰기만 다르면 있는 값으로 맞춘다. 값 합치기와 이름 바꾸기를 둔다.
- 개념의 꼬리표는 그 개념이 나온 자료들의 꼬리표를 모은 것으로 계산한다(색인). 그래서 "MYP 에서 배우고 DP 에서 다시 나온 개념" 같은 조합 탐색이 개념 단위로 된다.
- 과목 id 는 과목 꼬리표에서 만들고 수준을 넣지 않는다(`physics`, `math-aa`). 학년 중간에 HL 을 SL 로 내려도 경로와 개념 id 가 바뀌지 않는다.
- `meta/subjects.yaml`은 두지 않는다. 자료 폴더 경로에서도 과목을 뺀다(`sources/<자료 id>/`). 꼬리표를 고쳐도 자료가 옮겨 다니지 않는다.

자료는 하루하루 받은 파일 몇 개씩 들어온다. 그래서 넣기는 빨라야 하고, 꼬리표의 기본값은 마지막에 쓴 값이다. 단원과 강의 계획 항목은 학생이 정하지 않는다. 자료 읽기가 내용을 보고 제안한다(4).

### 22. 쪽 이미지를 주 입력으로 읽는다
2026-10-17 덧붙임.

PDF 로 내보낸 수학·과학 자료는 글자층에서 위첨자와 아래첨자가 사라지고(`2^x`가 "2x"), 공식과 문제가 그림으로 들어 있는 경우가 많다. 그래서 에이전트는 쪽 이미지를 주 입력으로 읽고, 글자층은 검색과 출처 대조에 쓴다. 슬라이드 애니메이션을 단계마다 내보내 앞 쪽을 조금씩 채워 가는 쪽이 이어지면 자료 넣기가 묶어 두고, 자료 읽기는 묶음의 마지막 쪽을 중심으로 읽는다. 이 묶기는 그런 쪽이 있을 때만 한다. 특정 선생님의 자료 모양을 가정하지 않는다.

### 23. 평가 과제의 답은 만들지 않는다
2026-10-17 덧붙임. 17 을 넓힌다.

형성평가, 총괄평가, 평가 기준(criteria) 연습처럼 평가받는 과제가 자료로 들어오면, 그 과제가 다루는 개념은 설명하되 과제 자체의 답과 풀이는 만들지 않는다.

### 24. 금지어를 두지 않는다
2026-10-17 덧붙임.

학생·학교·선생님 이름을 금지어로 적어 두고 웹 검색어와 산출물에서 막던 것을 뺀다. 개인 도구다. 검색어에 학교나 단원 이름이 섞여 검색 엔진에 남아도, 학습 페이지에 학교나 선생님 이름이 나와도 해가 되는 시나리오가 없다. Assayer 에서는 회사의 비공개 설계를 지키려고 둔 것인데, 근거를 다시 따지지 않고 옮겨 왔다. 남겨 두면 오탐(학교 약칭과 같은 낱말이 나오는 문제)으로 멀쩡한 결과를 버리는 제약만 된다.

- 외부 호출 검사 훅에는 로컬·사설망 주소 막기와 외부 호출 기록만 남긴다.
- `meta/privacy.yaml`과 관리자 설정의 금지어 칸을 뺀다.
- 공개 리포에 학생의 자료와 기록을 넣지 않는다는 규칙은 다른 일이라 그대로 둔다.

## 정하지 않은 것

| 무엇 | 메모 |
|---|---|
| Claude 계정 | 누구의 구독 토큰을 쓸지. 작업, 재생성, 마이그레이션의 사용량이 모두 그 계정에서 나간다. 관리자 계정이면 Assayer 와 5시간·주간 사용량을 나눠 쓴다 |
| 과목 가이드를 구할 수 있는지 | 학교가 가이드를 주면 항목까지 미리 만든다. 공개 과목 요약뿐이면 큰 주제만 먼저 만든다 |
| 학생 맥의 macOS 버전 | 배포 대상(deployment target)을 정한다. Assayer 는 26.0 이다 |
| 공통 부품의 첫 묶음 | 그림 블록이 함께 쓰는 부품. 테마 색, 글꼴, KaTeX, 슬라이더, 좌표축과 눈금, 단위 표시부터 권한다 |
