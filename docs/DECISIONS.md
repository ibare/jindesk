## 정한 것

### 1. Assayer 와 따로 만든다
Assayer 는 설계 검토와 PR 리뷰를 위한 앱이라 DP 과목, 강의 계획, 학습 화면을 다루는 방식이 아니다. 엔진의 실행 방식(격리된 `claude -p`, 러너가 결정적인 일을 하는 구조)만 옮겨 오고 앱은 새로 만든다.

### 2. 학생 한 명이 자기 맥에서 쓰는 Mac 앱이다
여러 사람, 배포, 계정 관리를 생각하지 않는다. 작업도 학생 맥에서 돈다. 관리자는 자기 맥에서 앱을 고치고 릴리즈한다.

> 2026-10-18 폰에서 읽기만 하는 iOS 앱을 더했다. 28 을 본다.

### 3. 작업은 Assayer 방식으로 돈다
작업마다 격리된 작업 공간에서 `claude -p --restricted`를 띄운다. 입력 고정, 산출물 검증과 배치는 러너가 한다. 에이전트는 작업 공간을 읽고 `out/`, `work/`에만 쓴다. 웹 호출은 검사 훅을 거친다.

### 4. 강의 계획 목차는 따로 만든다
자료를 넣을 때 강의 계획 항목을 고르게 하지 않는다. 미리 있는 목록이 아니기 때문이다. "목차 만들기" 작업이 과목 가이드, 공개 과목 요약, 선생님의 과정·단원 안내에서 목차를 만들고, 처음 한 번 사람이 확인한다. 자료 읽기가 엔트리마다 항목 코드를 제안하고 러너가 목차와 대조한다. 목차에 없으면 "목차 밖"에 둔다. DP 는 학년 초에 한 번 만들고, MYP 는 단원 안내가 올 때마다 단원이 더해진다.

> 2026-10-17 자료를 넣을 때 붙이는 값은 21 을 본다.

### 5. 학습 내용은 영어가 원문이고, 한국어는 문단마다 곁에 둔다
문서 전체를 한국어로 바꾸는 전환은 두지 않는다. 읽던 자리를 잃기 때문이다. 문단 끝의 단추로 그 문단 바로 아래에 한국어를 펼친다. 같은 영어 용어는 용어 어휘로 늘 같은 한국어로 옮긴다. 앱의 메뉴와 안내 글은 한국어다.

### 6. 그림은 블록 어휘 안에서 고른다
에이전트는 스크립트를 쓰지 않고 정해 둔 블록(수식, 그래프, 실험, 회로, 분자, 반응식 등)의 명세만 쓴다. 그리는 코드는 관리자가 짜서 앱 번들에 넣는다. 러너는 명세의 주장을 계산으로 확인한다(반응식 균형, 회로 전류, 확인 문제의 답). 블록 어휘에 없는 그림 요청은 관리자에게 "새 블록 요청"으로 간다.

> 2026-10-16 바뀌었다. 18 을 본다.

### 7. 출처를 단다
설명의 주장마다 자료와 쪽을 단다. 러너가 그 쪽이 있는지, 에이전트가 실제로 읽었는지 대조한다. 출처 없는 설명은 "보충"으로 따로 보인다.

### 8. 코멘트는 단위에 붙고 세 가지다
메모(학생만 본다), 질문("물어보기" 작업이 그 개념의 페이지와 원래 자료만 보고 답한다), "이상해요"(관리자가 지침을 고칠 때 본다). 코멘트는 단위 id, 판, 인용으로 자리를 찾는다.

> 2026-10-18 바뀌었다. 30 을 본다.

### 9. 부분 다시 만들기를 처음부터 고려한 구조로 둔다
페이지는 id 가 있는 단위(문단, 블록, 풀이 단계)로 이루어지고, 단위마다 판과 어디서 왔는지의 해시가 있다. 요구는 방식(더 쉽게, 더 자세히, 예시 더, 그림으로, 그림 다시, 단계 더, 고치기)을 고르고 메모를 붙인다. 요구는 데이터로 남아 나중에 페이지 전체를 다시 만들 때도 적용된다. 기능은 3단계에 만들지만, id·판·해시·요구 파일은 1단계부터 둔다.

### 10. git 을 쓰지 않는다
학생이 공부하며 git 과 GitHub 에 자료를 잇는 것은 불편하고 커밋도 문제가 된다. 모든 산출물은 데이터 폴더에 파일로 쓴다. 백업은 폴더를 통째로 한다(앱의 "백업 만들기"가 잠금을 잡고 만든다). 입력 고정은 커밋 해시 대신 내용 해시로 한다.

> 2026-10-18 바뀌었다. 28 을 본다.

### 11. 데이터 폴더는 앱이 정한 전용 폴더다
기본은 홈 아래 `~/Jindesk/`이고 처음 켤 때 바꿀 수 있다. 앱 번들 안에는 두지 않는다(업데이트 때 바뀌고 서명이 깨진다). iCloud 로 동기화되는 폴더는 경고한다. 다시 만들 수 있는 것(색인, 쪽 이미지, 작업 공간)은 데이터 폴더 밖에 둬서 백업을 작게 한다.

> 대화에서는 "앱 디렉토리"라고 했다. 학생이 찾아 통째로 백업하기 쉬운 보이는 폴더로 적었다. `~/Library/Application Support` 아래로 바꾸려면 `DATA.md`의 위치 한 곳만 바꾸면 된다.

### 12. 파일이 원본이고 SQLite 는 색인이다
사람이 읽는 파일은 YAML, 덧붙이는 기록은 JSONL, 작은 기계 기록은 JSON 이다. 에이전트는 JSON 만 쓰고, YAML 은 러너가 정해진 모양으로 쓴다. 화면은 이 파일들을 그때그때 조합해 그린다. SQLite 는 검색과 목록을 위한 색인이고, 캐시 폴더에 두며 언제든 파일에서 다시 만든다. SQLite 에만 있는 데이터는 없다.

### 13. 앱은 GitHub Releases 로 자동 업데이트한다
이 리포(`ibare/jindesk`, 공개)의 Releases 에 앱과 appcast 를 올린다. Sparkle 2 를 쓰고 업데이트 파일은 EdDSA 로 서명한다. 앱은 Developer ID 로 서명하고 공증한다(유료 개발자 계정이 있다). 작업이 돌고 있으면 설치를 미룬다.

### 14. 마이그레이션은 사본에서 하고 검증한 뒤 바꿔 끼운다
데이터 폴더에 스키마 버전을 둔다. 모양 변경은 결정적인 코드로 한다(관리자가 Claude Code 로 쓰고, 학생의 백업 사본으로 시험한다). 의미 변경만 에이전트 마이그레이션 작업이 하고, 결과는 러너가 검증한다. 학생이 쓴 글(코멘트, 메모, 요구의 메모)은 에이전트에 통과시키지 않고 바이트 그대로 옮긴다. 새 지침 때문에 내용을 다시 쓰는 것은 마이그레이션이 아니라 재생성이다.

### 15. 관리자와는 보내기·가져오기 묶음으로 주고받는다
git 이 없으니 관리자가 결과를 보는 길이 따로 필요하다. 학생이 "관리자에게 보내기"로 고른 코멘트("이상해요", 질문), 관련 페이지, 실패한 작업의 실행 기록, 버전 정보를 zip 으로 내보낸다. 메모와 원본 자료는 넣지 않는다. 관리자의 답글은 "가져오기 묶음"으로 돌아온다.

> 2026-10-16 바뀌었다. 20 을 본다.

### 16. 토큰은 키체인에만 둔다
Claude 토큰은 관리자가 설치할 때 키체인에 넣는다(`SETUP.md`). `.env`는 쓰지 않는다. 데이터 폴더를 통째로 백업하므로 거기에 토큰을 두면 백업에 함께 복사되기 때문이다. 러너는 자식 프로세스에만 토큰을 넘긴다.

### 17. 평가받는 글을 대신 쓰는 작업은 두지 않는다
IA, EE, TOK 에세이처럼 평가받는 글을 대신 쓰는 작업은 만들지 않는다. 앱은 이해를 돕는 데만 쓴다.

### 18. 그림과 인터랙션은 에이전트가 코드로 짠다
2026-10-16 덧붙임. 6 을 바꾼다.

블록 어휘 방식으로는 새 그림이 필요할 때마다 관리자가 명세 스키마, 러너 검사, 렌더러를 만들어 릴리즈해야 한다. IB 과목이 넓어 그림 종류에 끝이 없으니 관리자가 렌더러를 끝없이 만들게 되고, 그동안 학생의 요구는 멈춘다. 그래서 에이전트가 개념에 맞는 그림과 인터랙션을 HTML·JS 코드로 직접 짠다. 관리자는 블록 틀과 공통 부품(테마 색, 글꼴, KaTeX, 슬라이더, 좌표축 같은 것)만 만든다.

엄밀성 검사는 글에 둔다. AI 가 만드는 내용에서 틀림을 모두 없앨 수는 없다. 글이 바르게 서 있으면 학생이 이상한 그림을 알아챌 수 있지만, 글이 이상하면 앱의 결과 전체를 믿을 수 없다. 그래서 글은 지금처럼 출처, 주장 장부, 독자 시험, 격리 검증으로 확인하고, 그림은 러너가 돌아가는지(오류 없음, 그려짐, 멈추지 않음)만 본다. 그림이 틀리면 학생이 "이상해요"나 "그림 다시"로 고친다. 그림에만 계산 검사와 판정 에이전트를 붙이는 것은 들인 품에 비해 얻는 것이 적다.

보안은 이 앱에서 무게가 크지 않다(학생 한 명이 자기 맥에서 쓴다). 그림 블록을 블록마다 iframe 에 두는 것은 한 그림이 깨지거나 멈춰도 페이지의 나머지가 살아 있게 하려는 것이다.

수식(`math`)과 풀이(`derivation`)는 글에 가까우므로 지금처럼 데이터로 두고 검사한다.

### 19. 그림 블록은 라이브러리를 가리지 않고, 만들 때 받아 둔다
2026-10-16 덧붙임.

라이브러리를 미리 골라 번들에 넣으면 그것도 제약이 되어 그림의 선택지가 좁아진다. 그래서 에이전트는 필요한 JS 라이브러리를 CDN 주소로 마음대로 불러 쓴다. 러너는 그림을 만들 때(돌아가는지 확인할 때) 그 그림이 불러간 파일을 모두 데이터 폴더에 받아 두고, 보일 때는 그 사본을 쓴다. 그래서 보는 동안에는 네트워크가 없어도 되고, CDN 의 파일이 바뀌어도 그림은 그대로다.

이 앱에서는 소프트웨어 구조의 엄밀함보다 자료의 충실도와 학습 최신성이 먼저다. 둘이 부딪치면 앞의 것을 고른다.

### 20. 보내기·가져오기 묶음을 두지 않는다
2026-10-16 덧붙임. 15 를 바꾼다.

학생과 관리자는 같이 산다. 학생이 무언가를 원격으로 보낼 까닭이 없다. 관리자가 코멘트와 기록을 볼 때는 학생 맥에서 직접 보거나 백업을 가져와 읽는다. 그 방법은 관리자가 정하고, 앱에는 기능으로 두지 않는다. 관리자 답글(`reply`)과 살펴보기 모드도 함께 뺀다.

### 21. 과목·학년·수준은 미리 등록하지 않고 자료에 꼬리표로 붙인다
2026-10-17 덧붙임.

학년 > 과목 > 수준 같은 틀을 미리 만들지 않는다. 자료를 넣을 때 그 자료가 무슨 자료인지 꼬리표(학년, 과목, 수준)로 붙인다. Assayer 의 설계안 검토에서 프로젝트를 적듯이, 이전에 쓴 값과 미리 준비한 값에서 고르거나 직접 적는다. 과목 목록은 자료들에 붙은 꼬리표에서 모아 보인다.

- 꼬리표는 열린 이름-값이다. 학년·과목·수준은 처음 제안하는 이름일 뿐이고, 나중에 다른 이름(자료 종류, 단원 등)을 더해도 구조를 고치지 않는다.
- 수준도 정해진 값이 아니다. DP 의 SL/HL 만이 아니라 MYP 수학의 Standard/Extended 같은 값도 있다.
- 자유 입력이 갈라지지 않게, 적은 값이 이미 있는 값과 대소문자·띄어쓰기만 다르면 있는 값으로 맞춘다. 값 합치기와 이름 바꾸기를 둔다.
- 개념의 꼬리표는 그 개념이 나온 자료들의 꼬리표를 모은 것으로 계산한다(색인). 그래서 "MYP 에서 배우고 DP 에서 다시 나온 개념" 같은 조합 탐색이 개념 단위로 된다.
- 과목 id 는 과목 꼬리표에서 만들고 수준을 넣지 않는다(`physics`, `math-aa`). 학년 중간에 HL 을 SL 로 내려도 경로와 개념 id 가 바뀌지 않는다.
- `meta/subjects.yaml`은 두지 않는다. 자료 폴더 경로에서도 과목을 뺀다(`sources/<자료 id>/`). 꼬리표를 고쳐도 자료가 옮겨 다니지 않는다.

자료는 하루하루 받은 파일 몇 개씩 들어온다. 그래서 넣기는 빨라야 하고, 꼬리표의 기본값은 마지막에 쓴 값이다. 단원과 강의 계획 항목은 학생이 정하지 않는다. 자료 읽기가 내용을 보고 제안한다(4).

### 22. 쪽 이미지를 주 입력으로 읽는다
2026-10-17 덧붙임.

PDF 로 내보낸 수학·과학 자료는 글자층에서 위첨자와 아래첨자가 사라지고(`2^x`가 "2x"), 공식과 문제가 그림으로 들어 있는 경우가 많다. 그래서 에이전트는 쪽 이미지를 주 입력으로 읽고, 글자층은 검색과 출처 대조에 쓴다. 슬라이드 애니메이션을 단계마다 내보내 앞 쪽을 조금씩 채워 가는 쪽이 이어지면 자료 넣기가 묶어 두고, 자료 읽기는 묶음의 마지막 쪽을 중심으로 읽는다. 이 묶기는 그런 쪽이 있을 때만 한다. 특정 선생님의 자료 모양을 가정하지 않는다.

### 23. 평가 과제의 답은 만들지 않는다

### 24. 금지어를 두지 않는다
2026-10-17 덧붙임.

학생·학교·선생님 이름을 금지어로 적어 두고 웹 검색어와 산출물에서 막던 것을 뺀다. 개인 도구다. 검색어에 학교나 단원 이름이 섞여 검색 엔진에 남아도, 학습 페이지에 학교나 선생님 이름이 나와도 해가 되는 시나리오가 없다. Assayer 에서는 회사의 비공개 설계를 지키려고 둔 것인데, 근거를 다시 따지지 않고 옮겨 왔다. 남겨 두면 오탐(학교 약칭과 같은 낱말이 나오는 문제)으로 멀쩡한 결과를 버리는 제약만 된다.

- 외부 호출 검사 훅에는 로컬·사설망 주소 막기와 외부 호출 기록만 남긴다.
- `meta/privacy.yaml`과 관리자 설정의 금지어 칸을 뺀다.
- 공개 리포에 학생의 자료와 기록을 넣지 않는다는 규칙은 다른 일이라 그대로 둔다.

### 25. 자료가 밝힌 학습 목표를 이해의 기준으로 삼는다
2026-10-17 덧붙임.

첫 실제 자료 두 개로 만든 페이지를 견줘 보니, 슬라이드를 베끼지는 않았지만 설명의 깊이가 고르지 않았다. 계산 절차는 있는데 "이 값이 무엇을 뜻하나", "왜 그런가", "자료가 바뀌면 어떻게 되나"가 빠진 개념이 많았다. 그런데 바로 그것을 선생님이 자료의 학습 목표 쪽("Learning Outcome", "To Know")에 적어 두었고, 자료 읽기는 그 쪽을 수업 안내로 보고 건너뛰고 있었다.

- 수준(무엇을 다루나)은 자료를 따른다. 선행도, 쉬운 말로 내용을 줄이는 것도 하지 않는다.
- 설명의 깊이는 자료가 밝힌 학습 목표를 기준으로 본다. 자료 읽기가 목표를 그대로 뽑아 두고, 개념 정리와 학습 페이지 만들기의 러너 검사가 "이 글만 읽고 그 목표를 해낼 수 있는가", "그 목표를 연습하는 확인 문제가 있는가"를 판정한다.
- 목표를 해내는 데 자료에 없는 설명이 필요하면 보충(`added`)으로 쓴다. 새 개념이나 공식은 더하지 않는다.
- 미리 글을 어떻게 쓰라고 묶지 않고, 다 쓴 글을 목표에 비춰 본다. 목표가 없는 자료는 이 검사를 하지 않는다.

### 26. 개념 지도는 개념 파일에서 그때그때 그린다
2026-10-18 덧붙임.

개념마다 `prerequisites`가 있어 과목의 개념은 이미 선수 관계 그래프다. 학습 페이지의 "먼저 알아야 할 것"과 "다음 개념"만으로는 과목 전체에서 어디쯤인지 보이지 않아, 과목마다 개념 지도를 둔다(`PAGES.md`의 개념 지도).

- 지도를 파일로 저장하지 않는다. 작업이 끝날 때 다시 읽는 개념 목록에서 그릴 때마다 계산한다. 저장하면 개념 파일과 맞춰 두는 일이 하나 더 생긴다. 개념이 더해지거나 옮겨지면 지도도 따라 바뀐다.
- 자리는 목록 칸의 과목마다 맨 위 "개념 지도" 줄이다. 배치는 "배우는 순서"(선수 개념이 몇 겹 쌓였는지로 칸을 나눈다)와 "목차대로"(강의 계획 항목마다 한 칸) 둘 다 둔다.
- 과목 사이 연결(`links`)은 배우는 순서가 아니라서 지도에 그리지 않는다. 다른 과목의 개념은 선수 개념일 때만 그린다.
- 아직 없는 선수 개념(`missing:<제목>`)이 나중에 생겨도 지금은 저절로 이어지지 않는다. 개념 정리가 이번에 쓰는 개념의 선수 개념만 적기 때문이다. 지도에서는 같은 제목의 점선 노드와 실제 노드가 함께 보일 수 있다. 이어 주는 일은 개념 정리 쪽에서 따로 고친다.

### 27. 학습 페이지 머리에 앞뒤 개념만 그린 작은 지도를 둔다
2026-10-18 덧붙임. 26 을 넓힌다.

과목 지도는 따로 열어야 보이고, 페이지 아래의 "먼저 알아야 할 것"과 "이어서 배울 것"은 다 읽은 뒤에야 보인다. 페이지를 읽다가 앞뒤 개념으로 옮겨 다닐 수 있게, 학습 페이지 머리(관점 칩 아래, 첫 단위 위)에 이 개념의 바로 앞 선수 개념과 바로 다음 개념만 그린 지도를 둔다(`PAGES.md`의 개념 지도).

- 한 겹만 그린다. 그 너머로 더 이어지면 노드 바깥에 짧은 선만 단다. 전체는 "개념 지도에서 보기"로 과목 지도를 이 개념을 고른 채 연다.
- 이웃을 누르면 그 개념의 페이지로 간다. 새 페이지에서는 누른 노드가 가운데로 옮겨 오고, 떠나온 개념은 반대쪽 이웃으로 남는다. 그래서 돌아가기 단추를 따로 두지 않는다.
- 다른 과목의 개념은 앞뒤 어느 쪽이든 그린다. 과목 지도와 달리 끄지 않는다. 페이지에서 다른 과목으로 건너가는 길이기 때문이다.
- 학습 페이지가 아직 없는 개념도 누르면 옮겨 간다. 페이지가 없어도 그 개념의 앞뒤 지도는 보이므로 길이 끊기지 않는다.
- 페이지 아래의 "먼저 알아야 할 것"은 머리의 지도와 겹쳐 뺀다. "이어서 배울 것"은 다 읽고 이어 가는 자리라 남긴다.

### 28. 데이터 폴더를 비공개 GitHub 리포로 두고 맥과 폰이 나눈다
2026-10-18 덧붙임. 10 을 바꾸고 2 를 넓힌다.

폰에서도 만들어진 학습 페이지를 읽게 iOS 앱을 둔다. 맥 앱은 지금처럼 모든 일을 하고, 폰 앱은 맥이 만든 데이터를 받아 읽기만 한다. 둘 사이에 서버를 두는 것은 무겁다. 그래서 데이터 폴더를 GitHub 비공개 리포로 두고 맥과 폰이 나눈다(`DATA.md`의 데이터 리포, `MOBILE.md`).

- 맥 앱이 도는 맥에서 데이터 폴더는 그 리포를 클론한 작업 트리다. 맥 앱은 그 폴더를 데이터 폴더로 쓰며 커밋하고 올린다. 작업, 잠금, 마이그레이션은 지금처럼 로컬 파일에서 한다.
- 어느 리포를 쓸지는 그 맥의 앱 설정에서 정한다. 리포가 데이터 폴더에 붙어 다니면, 개발 맥에서 학생의 백업을 풀어 열었을 때 시험 결과가 학생의 실제 리포로 올라갈 수 있다. 앱 설정에 두어 개발 맥은 시험 리포로, 학생 맥은 실제 리포로 가른다. 앱은 열 때 폴더의 원격이 설정한 리포와 같은지 보고, 다르면 올리지 않는다.
- 인증은 그 리포만 읽고 쓸 수 있는 fine-grained 토큰이다. 앱 설정에서 넣고 키체인에 둔다(16). git 을 띄울 때만 자격 증명으로 넘기고 `.git/config`에는 적지 않는다.
- 연결하는 리포는 둘 가운데 하나다. 아무것도 없는 빈 리포면 앱이 데이터 폴더를 새로 만들어 첫 커밋을 올린다. Jindesk 데이터 폴더 모양의 리포면 클론해서 연다. 새 맥으로 옮기거나 앱을 다시 깔아도 리포에서 되살아난다.
- 리포를 바꾸면 새 리포를 연결하기만 한다. 이전 리포와 그 클론은 건드리지 않는다.
- 쓰는 쪽은 그 리포에 연결한 맥 하나다. 켤 때 원격이 앞서 있으면 받아서(fast-forward) 연다. 기록이 갈라졌거나 올리지 못하면 앱 창에 보인다.
- 원본 자료와 쪽 이미지는 리포에 넣지 않고 자료 버킷(GCS)에 둔다(31). 그 밖에 GitHub 이 받지 않는 100MB 이상 파일도 뺀다.
- 10 에서 git 을 뺀 까닭은 학생이 git 과 GitHub 을 다뤄야 한다는 것이었다. 리포 연결은 관리자가 앱 설정에서 하고, 커밋과 올리기는 앱이 한다.
- 입력 고정은 지금처럼 내용 해시로 한다.
- 폰 앱은 이 리포의 `ios/`에 둔다. 폰 앱의 범위와 화면은 29 를 본다.

### 31. 원본 자료와 쪽 이미지는 GCS 버킷에 둔다
2026-10-18 덧붙임. 28 과 29 의 쪽 이미지를 바꾼다.

한 학년에 수학만 해도 자료 파일이 100여 개이고, 파일마다 30~60쪽이다. 쪽 이미지까지 git 리포에 넣으면 처음부터 1GB 를 넘고, git 은 이력이 줄지 않아 해마다 커지기만 한다. 원본 자료도 같다. 그래서 git 리포에는 글 데이터만 두고, 원본 자료와 쪽 이미지는 GCS 버킷에 둔다(`DATA.md`의 자료 버킷).

- 리포에는 YAML, JSONL, 그림 블록 코드, 글자층 같은 글 데이터만 둔다. 원본 자료(`original.*`, `source.pdf`)와 쪽 이미지는 자료 버킷에 둔다.
- 버킷도 리포처럼 개발 맥용과 학생 맥용으로 나눈다. 어느 버킷을 쓸지는 그 맥의 앱 설정에서 정한다. GCS 는 관리자의 개인 Google 계정 프로젝트에 둔다.
- 인증은 서비스 계정 둘의 HMAC 키다. 맥은 쓰기용, 폰은 읽기 전용이고, 각 앱 설정에서 넣어 키체인에 둔다.
- 쪽 이미지는 한 벌만 만들고 맥과 폰이 같은 것을 본다. HEIC 이고 긴 변 2000px 이다. 폰에서는 폭에 맞추면 글자가 작아 확대해 읽어야 하고, 2000 이면 2배 확대에서도 작은 글자와 첨자가 또렷하다(177쪽 기준 쪽당 평균 94KB).
- 맥은 자료를 넣을 때 모든 쪽의 이미지를 만들어 로컬에 두고 버킷에 올린다. 맥은 로컬 이미지를 보고, 폰은 출처를 누를 때 그 쪽만 버킷에서 받는다.
- 쪽 보기는 맥과 폰 모두 확대할 수 있다(4배까지, 두 번 눌러 2배).
- 리전은 두바이에서 가장 가까운 me-central1(도하)이다. 버킷은 관리자 개인 계정에 새로 만든 Jindesk 전용 프로젝트에 둔다.
- 에이전트가 읽는 쪽 이미지(PNG, 긴 변 1600)는 따로 둔다. Claude 는 HEIC 를 읽지 않는다.
- 원본은 맥의 데이터 폴더와 버킷에 있고, 폰은 받지 않는다. 새 맥이나 다시 깐 앱에서는 리포를 클론하고, 원본과 쪽 이미지는 쓸 때 버킷에서 받는다.
- 이미 넣은 자료는 쪽 이미지를 한 번 만들어 원본과 함께 올린다.

### 32. 맥의 목록 칸을 다시 그린다
2026-10-18 덧붙임.

과목, 오늘, 모아 보기의 목록이 모든 줄을 같은 모양(이름과 회색 설명)으로 늘어놓아 무엇이 중요한지 보이지 않았다. 긴 영어 이름이 두 줄로 넘어가 줄 높이가 들쭉날쭉했고, 개념 지도와 자료 같은 다른 종류의 줄이 개념 줄 사이에 섞여 있었다.

- 목록 칸 위에는 사이드바에서 고른 화면의 이름을 둔다.
- **개념 줄.** 영어 이름의 콜론 앞과, 그 아래에 한국어 이름의 콜론 앞을 한 줄씩 보인다. 넘치면 줄임표로 줄인다. 고른 줄만 펼쳐 이름의 나머지와 자료의 쪽, 확인 문제 수를 보인다.
- 오른쪽에는 상태를 둔다: 7일 안에 정리된 개념의 점(앱 아이콘의 리본 색), 메모 수, 페이지를 만드는 중, 한국어가 남은 곳.
- 같은 묶음 안의 개념은 배우는 순서(개념 지도의 배우는 순서)로 놓는다. 번호는 붙이지 않는다. 선수 관계가 없는 개념에도 차례를 매기는 것처럼 읽히고, 개념이 늘면 번호가 바뀐다.
- **과목.** 과목 이름은 세리프로 쓴다(앱 아이콘의 J, 학습 페이지 제목과 같은 결). 아래에 학년·수준, 개념 수, 자료 수를 둔다. 과목을 접을 수 있고, 과목 메뉴는 마우스를 올릴 때 보인다. 개념 지도는 과목 머리 아래의 카드로 두고, 자료는 과목 맨 아래의 "자료 N개 · M쪽" 줄을 펼쳐 본다.
- **오늘.** 지난 7일 동안 넣은 자료마다, 그 자료에서 정리된 개념을 묶어 보인다. 멈춘 일과 고를 새 판은 맨 위의 할 일에 둔다. 답이 온 질문은 뺀다(30).
- **모아 보기.** 탭 이름을 연결, 자료, 문제, 메모로 줄인다. 확인 문제는 개념마다 묶어 배우는 순서로 놓고, 답을 목록에서 펼쳐 본다. 과목으로 거를 수 있다.
- 목록의 글은 수식의 아래첨자와 위첨자를 글자로 바꿔 보인다(Q₁, x²).

### 33. 앱에는 역할이 없다
2026-10-19 덧붙임. `ARCHITECTURE.md`의 설정에서 "학생 화면에는 보이지 않는다"를 바꾼다.

앱은 하나이고 쓰는 사람을 나누지 않는다. "학생 화면"과 "관리자 설정"을 나누지 않는다.

- 설정 창의 이름은 "설정"이다. 앱 메뉴의 "설정…"(⌘,)으로 열고, 숨기지 않는다.
- 화면의 글은 누구에게 알리라고 하지 않는다. 할 일이 있으면 그 자리(설정의 환경 점검 등)를 가리킨다.

### 34. 자료를 사전처럼 모아 보는 학습 도구
2026-10-19 덧붙임. 32 의 모아 보기 탭을 바꾼다.

이 앱은 자료를 사전처럼 모아 정리하는 앱이다. 학습 진척을 재는 앱이 아니다. 이미 쌓이는 데이터(용어집, 개념의 기호와 주장, 관점, 레퍼런스, 학습 페이지의 상자와 풀이, 원래 자료의 글자층)로 다음을 둔다.

- **찾기.** 개념에 더해 용어(영어 ↔ 한국어), 기호, 원래 자료의 쪽(글자층)을 찾는다.
- **단원 개요.** 과목 목록에서 단원 이름을 누르면 내용 칸에 연다. 한 장 요약, 공식과 풀이, 용어와 기호, 자주 하는 실수, 더 볼 자료, IB 맥락(탐구 진술, 핵심·관련 개념, TOK, command terms)이 있다.
- **한 장 요약은 새 문장을 쓰지 않는다.** 개념 원문 단위의 주장(출처 대조, 주장 장부, 격리 검증을 거친 것) 가운데 고른 것을 글자 그대로 보이고, 줄마다 근거 쪽을 단다. 고르기는 관점 붙이기가 주장 id 로 하고 `facets.yaml`에 적는다. 러너는 id 가 그 개념의 주장인지만 본다. 개념 원문이 바뀌면(`from` 해시) 관점과 함께 다시 고른다. 공식도 같은 방식으로 고른다. 이미 있는 개념은 고른 것이 없으므로 남은 일로 관점 붙이기를 다시 돈다.
- **학습 페이지.** command term 칩을 누르면 IB 정의가 뜨고, 용어집의 용어에 마우스를 올리면 한국어가 뜬다. "자료와 나란히"를 켜면 지금 읽는 문단의 근거 쪽이 옆에 따라 나온다.
- **모아 보기.** 범주 열한 개(사전: 용어, 기호, Command terms · 모음: 공식, 실수, 더 볼 자료, IB 맥락, 연결 · 내 것: 문제, 메모, 자료)를 칩으로 고른다. 목록은 첫 글자로 묶고 오른쪽에 A–Z 인덱스를 둔다. 용어, 기호, command terms, IB 맥락은 그 말의 첫 글자로, 나머지는 개념 이름의 첫 글자로 묶는다.
- **Command term 의 정의**는 IB 과목 가이드의 command terms 용어집을 앱에 넣어 둔다.
- **폰.** 찾기(용어, 기호, 개념)와 단원 요약을 읽는다.
- **하지 않는 것.** 목차 진도(진척을 재지 않는다), 자료의 쪽과 개념 대응 화면. 시험 준비는 따로 다시 기획한다.

### 35. 자료 묶음이 작업 단위다
2026-10-19 덧붙임. 21 의 "자료 넣기는 파일마다"와 JOBS.md 의 "자료 읽기는 자료 하나, 개념 정리는 과목 하나"를 바꾼다.

파일 이름은 불완전하고, 어느 슬라이드와 어느 워크시트가 짝인지는 넣는 사람만 안다. 지금까지는 파일마다 따로 읽고, 같은 개념인지는 개념 정리 에이전트가 제목을 실마리로 판단했다. 러너는 그 판단을 검사하지 않았고, 정리가 읽기를 기다리지 않아 같은 페이지를 되풀이해 만들었다.

- **묶음.** 자료를 넣을 때 같은 내용을 다루는 파일을 한 묶음으로 넣는다. 붙이는 것은 메모뿐이다. 묶음의 이름은 받지 않고, 묶음 읽기가 자료 내용으로 짓는다. 크기 상한은 두지 않는다(한 세션의 맥락 창이 약 400쪽에서 찰 수 있다는 것만 안다).
- **묶음 읽기.** 에이전트 하나가 묶음의 읽지 않은 자료를 함께 읽는다(1차·2차). 엔트리는 여러 자료에 걸칠 수 있고, 주장마다 자료와 쪽을 단다. 이미 읽은 자료가 있는 묶음(나중에 더한 자료)은 더한 자료만 읽고, 묶음의 기존 엔트리를 함께 받아 같은 개념에 같은 제목을 쓴다.
- **묶음 정리.** 묶음의 읽기가 끝나면 그 묶음의 엔트리를 모두 한 번에 정리한다. 그 뒤에 그 묶음이 바꾼 개념의 페이지, 번역, 관점을 만든다.
- **묶음은 주제 하나의 경계가 아니다.** 선생님 자료에는 여러 주제가 섞인다(워크시트 끝의 지난 단원 복습처럼). 그런 내용도 빼지 않고 엔트리로 쓴다. 개념 정리는 그 묶음의 단원에만 붙이지 않고 과목 전체에서 보충할 개념을 찾는다. 이 앱의 가치는 엉망인 자료를 잘 정리해 내는 데 있다.
- **보류는 끝이 아니다.** 개념 정리가 보류한 엔트리는 그 과목의 다음 정리마다 까닭과 함께 다시 받는다. 맞는 개념이 생기면 붙인다. 자료 읽기에서 학생 독자 시험에 고쳐 써도 떨어진 엔트리도 버리지 않고 보류로 남겨, 그 주장과 예제를 나중에 보충 재료로 쓴다.
- **묶음 고치기.** 메모를 고치고, 자료를 다른 묶음이나 새 묶음으로 옮긴다. 합치기는 한 묶음의 자료를 모두 옮기는 것이다. 이미 끝난 읽기와 정리는 되돌리지 않고, 아직 하지 않은 일만 옮긴 묶음에서 한다.
- **목차의 근거.** 목차의 근거로 넣는 파일(과목 가이드, 과정·단원 안내)은 파일마다 묶음 하나가 된다. 지금처럼 읽고, 목차 만들기에도 쓴다.
- **묶음 파일이 없는 자료.** 자료 하나가 묶음 하나인 혼자인 묶음으로 본다.

### 36. 출시 전에는 데이터 판을 올리지 않는다
2026-10-19 덧붙임. MIGRATION.md 의 규칙은 출시 후부터 쓴다.

관리자가 정하기 전까지 스키마 버전과 파일의 판(`v`)은 모두 1 이다. 데이터 모양을 바꾸면 판 1 의 모양 자체를 고치고, 마이그레이션 단계와 옛 모양을 읽는 코드를 두지 않는다. 출시 전이라 지킬 학생 데이터가 없고, 개발 데이터는 새로 만든다. 34 와 35 때 올렸던 스키마 2·3 과 그 마이그레이션 단계는 되돌렸다. 판은 출시 후 관리자가 올리기로 정할 때 올린다.

### 37. 데이터 리포는 마지막 상태로 판단한다
2026-10-19 덧붙임. 28 의 "아무것도 없는 빈 리포"를 바꾼다.

리포가 빈지는 커밋이 있느냐가 아니라 마지막 상태에 무엇이 있느냐로 본다. 연결하거나 켤 때 리포의 마지막 상태를 받고, 비어 있으면(리포 기본 파일 `README*`, `LICENSE*`, `.gitignore`, `.gitattributes`만 있는 것 포함) 그 자리에 데이터 폴더를 새로 만들어 커밋해 올린다. `meta/schema.yaml`이 있으면 연다. 다른 파일이 있으면 연결하지 않고 그 파일들을 알린다. 그래서 데이터를 처음부터 다시 만들 때 리포를 지우고 다시 만들 필요 없이 파일을 모두 지우면 된다. "더 새 판" 화면에서도 리포를 바꾸러 갈 수 있다.

### 38. 예제에도 출처를 달고, 엔트리 하나를 여러 개념이 나눠 쓴다
2026-10-19 덧붙임. 35 의 묶음 읽기와 묶음 정리를 실제로 돌려 본 뒤 고친다.

- **예제의 출처.** 워크시트가 묶음에 주는 몫은 대개 연습 문제와 답이다. 그런데 엔트리의 예제는 글뿐이라, 개념 정리가 그 예제를 단위로 옮겨도 근거 쪽을 달지 못했다(주장으로 달지 못하고 글에만 넣었다). 이제 자료 읽기가 예제마다 자료와 쪽을 단다. 개념 정리는 예제를 단위로 옮길 때 그 출처를 주장으로 단다. 그래서 학습 페이지의 근거 칩과 "자료와 나란히"에 워크시트 쪽이 나온다.
- **엔트리 나눠 쓰기.** 엔트리 하나는 개념 하나에만 들어갈 수 있었다. 그래서 큰 엔트리(묶음 읽기에서 슬라이드 수십 쪽과 워크시트를 아우르는 것)가 단위 여덟을 넘는 개념 하나로 묶였다. 이제 엔트리 하나를 여러 개념이 나눠 쓴다. 각 개념은 그 엔트리의 출처를 쓸 수 있다. 보류와 개념에 함께 둘 수는 없다. 러너는 엔트리의 주장이 그 엔트리를 쓰는 개념들의 단위 어딘가에 남았는지 본다. 빠진 것이 있으면 한 번 고쳐 쓰게 하고, 그래도 남으면 기록에 남긴다(정리를 실패시키지 않는다).
- **보충 단위는 그대로 둔다.** 학습 목표 시험 때문에 자료에 없는 풀이와 증명이 보충 단위로 늘어나는 것은 화면에 "보충"으로 구분되므로 지금은 그대로 둔다. 학생이 써 보며 피드백을 준 뒤 고친다.

### 39. 과목 목록은 단원으로 들어가는 스택이다
2026-10-19 덧붙임. 32 의 과목 목록을 바꾼다. 시안은 Jindesk 과목 스택 시안 캔버스다.

자료 폴더 둘을 넣자 한 과목의 개념이 35개가 되었고, 자료를 다 넣으면 과목마다 수백 개가 된다. 한 목록에 단원 머리와 개념을 모두 늘어놓으면 단원이 묻히고 굵은 줄이 벽처럼 늘어선다. 지어낸 개념 네 개로 그린 32 의 시안에서는 보이지 않던 문제다.

- **사이드바.** "과목"은 누를 수 없는 이름표다. 그 아래에 과목이 늘 펼쳐져 있고, 과목을 고르면 목록 칸이 그 과목을 연다.
- **목록 칸은 스택이다.**
  - 과목 단계: 과목 머리(세리프 이름, 학년·수준 · 단원 수 · 개념 수, 과목 메뉴), 개념 지도 카드, 단원 목록. 단원 줄에는 이름과 개념 수가 있다.
  - 단원 단계: 단원 줄을 누르면 들어간다. 맨 위의 "‹ 과목 이름"으로 돌아간다. 단원 머리가 고른 채로 남고 내용 칸에 단원 요약이 열린다. 그 아래에 단원의 개념이 배우는 순서로 놓인다. 단원 머리를 다시 누르면 단원 요약으로 돌아간다.
  - 다른 곳(앞뒤 개념, 개념 지도, 찾기, 오늘)에서 개념을 열면 목록 칸이 그 개념의 단원까지 따라 들어간다.
- **단원의 차례는 이름의 알파벳순이다.** 단원 사이의 배우는 순서는 데이터로 정할 수 없다. 단원을 잇는 선수 관계가 거의 없다(이 결정 때 단원 10 개 사이에 하나). 목차가 생기면 목차의 차례를 다시 본다.
- **개념 지도 카드는 과목 단계 맨 위에만 둔다.**
- **목록에서 뺀 것.** 과목 맨 아래의 자료 줄과 과목 머리의 자료 수를 뺀다. 자료는 모아 보기의 자료에서 본다. 고른 개념 줄에서 자료의 쪽과 확인 문제 수를 뺀다. 이름의 나머지만 펼친다.
- **새로 정리된 개념은 하루다.** 개념 줄의 점과 개념 지도의 "새로"는 그 개념을 정리한 작업(`provenance.job`)이 24시간 안일 때 붙는다. 7일은 거의 모든 줄에 점이 붙어 아무것도 구별하지 못했다. 단원 줄과 사이드바의 과목 줄에도 그 안에 새 개념이 있으면 점을 단다. 스택에서는 개념이 단원 안에 숨기 때문이다. 오늘 화면의 7일(넣은 묶음)은 그대로다.
- **폰도 같다.** 첫 화면의 과목 → 단원 목록(맨 위에 개념 지도) → 단원의 개념 목록(맨 위에 단원 요약) → 학습 페이지로 들어간다.

### 40. 앱이 끝나면 멈춘 작업과 대기열을 다음에 켤 때 다시 넣는다
2026-10-19 덧붙임. `ARCHITECTURE.md`의 비정상 종료를 바꾼다.

전에는 앱이 비정상 종료하면 다음에 켤 때 진행 중이던 작업을 중단됨으로 고치기만 했다. 대기열은 메모리에만 있어 사라졌고, 학생이 "이어서 하기"를 눌러야 다시 돌았다. 자료 넣기는 묶음의 파일을 모두 넣은 뒤에 묶음 파일을 써서, 넣다가 꺼지면 들어간 자료가 묶음과 메모를 잃고 혼자인 묶음으로 흩어졌다. 띄운 claude 는 별도 프로세스 그룹이라 앱과 함께 끝나지 않았다.

- **진행 중이던 일은 버린다.** 다시 넣은 작업은 처음부터 한다. 작업 공간의 중간 결과를 이어 쓰지 않는다.
- **넣을 때의 정보는 남긴다.** 작업을 대기열에 넣을 때 `run.json`에 다시 준비할 입력과 넣은 프로세스를 쓴다.
- **다음에 켜면 저절로 다시 넣는다.** 시작했던 작업부터, 그다음 대기열의 차례로 넣는다. 넣은 프로세스가 살아 있는 작업(명령줄)은 건드리지 않는다. 토큰이 없으면 에이전트 작업은 넣지 않고 "이어서 하기"에 맡긴다. ⌘Q 로 끝내도 같다. 작업마다 누른 취소는 다시 넣지 않는다.
- **다시 할 때마다 앱이 끝나는 작업.** 저절로 다시 넣으므로, 앱을 끝내는 자료(망가진 파일 같은 것)가 있으면 켤 때마다 다시 끝난다. 진행 중에 비정상 종료한 작업은 두 번까지만 다시 넣고, 세 번째에는 알리고 넣지 않는다. ⌘Q 로 끝낸 것은 세지 않는다.
- **자료 넣기.** 새 묶음의 id 를 준비할 때 정해 둔다. 자료를 하나 넣을 때마다 바로 그 묶음에 적는다. 다시 시작하면 꺼지기 전에 넣은 자료는 넣은 것으로 친다. 묶음에 적기 전에 꺼져 혼자인 묶음으로 남은 자료(넣기를 처음 준비한 뒤에 받은 자료)도 제 묶음에 넣는다. 메모는 한 번만 적힌다. 그사이 없어진 파일은 까닭을 남기고 뺀다.
- **띄운 프로세스.** 프로세스 그룹마다 리더의 PID 와 시작 시각을 앱 지원 폴더의 `children/`에 적는다. 앱과 명령줄은 켤 때, 띄운 프로세스가 끝났는데 남은 그룹을 그룹째 끝낸다. 시작 시각이 다르면 PID 를 다른 프로세스가 받은 것이라 건드리지 않는다.

### 41. 여러 수업이 든 파일은 수업마다 자료로 쪼갠다
2026-10-19 덧붙임. 35 의 묶음 단위를 보탠다.

지금까지는 파일 하나가 묶음 하나였고, 묶음 하나를 자료 읽기 한 번과 개념 정리 한 번이 다뤘다. 수학 자료는 파일 하나가 수업 하나라 맞았다(가장 큰 것이 97쪽, 엔트리 9개). 물리 단원 자료는 7주 21차시가 파일 하나(169쪽)에 들어 있었다. 이대로면 한 번의 읽기가 169쪽을 모두 보고, 한 번의 정리가 엔트리 수십 개를 다룬다. 시간 상한에 걸리면 정리가 통째로 반영되지 않고, 다시 해도 크기가 같다. 개념마다 단원 전체의 학습 목표(약 50개)를 받는 것도 문제다.

- **자료 나누기 작업을 둔다.** 자료 넣기 뒤, 자료 읽기 앞에 돈다. 에이전트가 쪽마다의 글자층으로 자료가 스스로 표시한 수업(차시) 경계를 찾는다. 과목은 가리지 않는다.
- **자료가 표시한 경계로만 나눈다.** 내용으로 주제를 짐작해 나누지 않는다. 수업 하나짜리나 경계가 분명하지 않은 자료는 나누지 않는다. 주가 아니라 수업이 단위다.
- **수업마다 새 자료로 쪼갠다.** 원래 PDF 에서 그 쪽들을 잘라 새 자료를 만들고, 수업마다 묶음 하나를 둔다. 원래 자료는 지운다. 묶음이 쪽 범위를 가리키게 하는 방법도 있었지만, 묶음 파일, 읽은 자료 판정, 정리할 엔트리 판정, 남은 일 계산, 묶음 화면이 모두 쪽 범위를 알아야 한다. 쪼개면 읽기, 정리, 출처, 쪽 보기, 폰, 자료 버킷이 지금 그대로 돈다. 학습 목표도 수업마다로 저절로 좁혀진다.
- **출처의 쪽은 수업 안의 쪽이다.** "Class 3 · 4쪽"처럼 보인다. 원래 파일의 쪽 범위는 `meta.yaml`의 `split_from`에 남는다.
- **원래 파일은 해시로 기억한다.** 같은 파일을 다시 넣으면 `split_from`의 해시로 알아보고 뺀다.
- 실제 물리 단원 파일로 돌려 보니, 글자층만 읽고 7턴 만에 차시 표지("Class N of 21")를 경계로 21개(대부분 8쪽)로 나눴다.

### 44. 언어 습득 과목은 주제가 아니라 문법, 낱말, 표현을 축으로 정리한다
2026-10-20 덧붙임.

스페인어 학습 페이지가 문법과 쓸모 있는 낱말보다 단원 주제 이야기로 흘러 사회 과목 수업 같다는 학생 의견이 있었다. 영어로 해설하는 것은 괜찮다고 했다. 받은 데이터를 보니 개념이 "~에 대해 말하기" 같은 주제 단위로 짜였다. 단원 틀 슬라이드(탐구 진술, 지속가능발전목표, ATL, 학습자상, 수업 활동 방법)도 개념이 되었다. 학습 목표의 "Explain"을 까닭 설명으로 읽어 주제 내용의 까닭을 묻는 확인 문제가 생겼다. 지침이 내용 과목의 모양이었다: 개념 하나는 질문 하나, 명령어는 까닭과 해석으로, 보충은 이해에 필요한 설명으로. 학습 목표 시험의 판정자도 explain 을 "왜 그런지"로 판정했다.

- **과목 이름으로 알아본다.** 과목 꼬리표 값에 외국어 이름(Spanish, French …)이 있거나 언어 습득 표시(Language Acquisition, Language B, ab initio, "English B"처럼 끝의 B)가 있으면 언어 습득 과목이다. 영어와 문학 과목(Language A, Language and Literature, "Spanish A"처럼 줄여 적은 것)은 아니다. 한자, 가나, 한글로 쓰는 언어(Mandarin, Chinese, Japanese, Korean)도 아직 다루지 않는다. 목표 언어를 철자 그대로 쓰면 영어 칸과 한국어 칸의 한글·한자·가나 검사에 걸려 작업이 막히기 때문이다. 그런 과목이 생기면 그 언어에 한해 검사를 어떻게 풀지 따로 정한다. 자료를 넣을 때 따로 표시하지 않는다. 러너가 정해 작업 요청에 적으므로 모든 작업과 판정자가 같은 판단을 쓴다. 목록에 없는 언어는 코드에 더한다.
- **개념은 언어 단위다.** 문법 요점, 낱말 세트, 표현 묶음, 글 종류 가운데 하나다. 단원 주제는 예문의 배경으로만 쓰고, 주제에 대한 사실과 사회적 설명은 쓰지 않는다. 같은 문법이 여러 단원에 나오면 한 개념에 모은다.
- **단원 틀은 엔트리로 두고 보류한다.** 자료 읽기가 단원마다 `Unit frame: <단원 이름>` 엔트리 하나로 모으고, 개념 정리가 "단원 틀"로 보류한다. 빼지 않으므로 엉망인 자료도 엔트리로 두는 원칙과 맞는다. 단원 요약에 담을 자리는 두지 않았다. 새 자리를 두면 데이터 스펙이 바뀌어 판을 올려야 한다. 목차의 MYP 자리(`myp`)는 목차의 근거로 넣은 단원 안내가 있을 때 쓰인다.
- **학습 목표는 목표 언어로 해내는 것이다.** Explain, Describe, Talk about 은 주제를 목표 언어로 말하고 쓰는 일이다. 학습 목표 시험도 그렇게 판정한다. 필요한 문법, 낱말, 표현, 예문이 글에 있는지와 목표 언어를 쓰거나 읽는 확인 문제(활용, 문장 만들기, 고쳐 쓰기, 짧은 읽기)가 있는지를 본다. 주제 내용의 까닭은 묻지 않는다.
- **보충은 언어를 채운다.** 단원이 다룬다고 밝힌 문법의 핵심 표(불규칙 동사의 활용 전체 같은 것)와 쓸모 있는 표현 묶음은 슬라이드에 없어도 보충 단위로 채운다. 주제의 사회적 설명은 보충하지 않는다.
- **설명은 그대로 영어다.** 목표 언어의 낱말과 예문은 기울임으로 쓰고 영어 뜻을 붙인다. 활용과 낱말 목록은 나열로 쓴다(표는 쓰지 않는다). 한국어 층은 목표 언어를 옮기지 않고 같은 자리에 둔다. 번역 검사는 영어 단위에 그대로 나온 영어가 아닌 언어의 글을 남은 영어로 세지 않는다. 영어인지는 언어 인식으로 가린다. 그래서 옮기지 않은 영어 설명은 그대로 잡힌다.
- **고침 (PR #7).** 학생 데이터 사본으로 다시 정리를 시험하니, 한국어 층의 스페인어 낱말 나열("el doctor, la veterinaria, la enfermera")이 남은 영어로 잡혔다. 영어 단위에는 낱말마다 괄호 뜻이 붙어 구절 모양이 달랐다. 이 검사가 잡는 것은 남은 영어이므로, 영어 단위에 그대로 나왔는지는 보지 않고 언어 인식만으로 영어인지 가린다. 옮기지 않은 영어 설명과 영어 낱말 나열은 그대로 잡힌다. 검사 규칙이 바뀌었으므로 번역 지침은 0.6 이다.
- **번역 검사는 그 과목의 용어만 본다.** 학습 페이지가 밑줄로 보이는 용어와 같게, 그 과목의 용어와 과목이 적히지 않은 용어만 본다. 학생 데이터의 사본으로 시험하니 스페인어 페이지의 영어 설명에 수학 용어(mean, reflection, class)가 걸려 페이지마다 고쳐 쓰기가 한 번씩 더 돌았다. 한국어를 쓰는 작업(번역, 물어보기, 부분 다시 만들기)의 에이전트가 받는 어휘도 그 과목의 것만이다. 번역이 다른 과목에만 달린 용어를 다른 한국어로 제안하면 그 용어에 이 과목을 더하지 않고 충돌로만 남긴다. 더하면 다른 과목의 한국어가 이 과목에 묶여 같은 오탐이 되살아난다.

### 47. 고른 개념은 다시 정리해 대응표를 보고 반영하고, 코멘트와 요구는 단위까지 따라간다

### 48. 찾기는 낱말로 나눠 찾고, 찾은 곳으로 데려간다
2026-10-21 덧붙임. 34 의 찾기를 고친다.

학생이 찾기가 제한적이라고 했다. 학생 데이터 사본(개념 250, 단위 4,882, 자료 1,305쪽)에 질의 38개를 앱과 같은 규칙으로 던져 보니 다음에서 막혔다.
- 친 말 전체를 한 구절로 찾는다. 낱말 차례가 다르거나 사이에 낱말이 있으면 0개다(`logarithm laws` 0, `laws of logarithms` 7).
- 결과 상한이 단위 40개라 흔한 말은 개념 일부만 보인다(`force`는 47개 가운데 17). 두 글자 한국어는 순위 없이 파일 차례로 나온다.
- 악센트를 빼고 친 스페인어를 못 찾는다(`espanol` 0). 오타를 받아 주지 않는다. 과목으로 가를 수 없다.
- 찾은 개념을 열면 페이지 맨 위가 열린다. 페이지 안에서 찾기가 없다.
- 폰은 개념 이름만 찾는다.

- **낱말로 나눠 찾는다.** 따옴표로 묶은 것은 구절 하나다. 한 단위 안에 모든 낱말이 들어 있어야 맞는다. 세 글자 이상은 trigram 색인으로, 짧은 낱말은 글 전체에서 찾는다.
- **악센트와 대소문자를 가리지 않는다.** 두 글자 이하의 낱말은 악센트를 가린다.
- **개념 단위로 순위를 매긴다.** 이름에 모든 낱말이 든 개념, 친 말이 그대로 든 개념, 맞은 단위가 많은 개념 차례다. 상한은 개념 100개다. 개념마다 맞은 곳의 앞뒤 글을 셋까지 든다.
- **결과가 없으면 비슷한 말을 제안한다.** 색인 글의 라틴 문자 낱말(네 글자 이상)에서 편집 거리가 가까운 것을 셋까지 보인다. 다섯 글자까지는 거리 1, 그보다 길면 2 까지다.
- **과목으로 거른다.** 결과가 두 과목 이상에 걸치면 결과 위에 과목 칩(개수)을 둔다.
- **찾은 곳으로 데려간다.** 결과에서 개념을 고르면 첫 맞은 문단까지 내려 열고, 페이지 안의 찾은 말에 표시를 한다. 페이지 안 찾기(맥 ⌘F, 폰은 찾기 단추)로 다음과 이전을 오간다. 접힌 한국어 층 안에서 맞으면 그 층을 펼친다. 이 기능은 렌더러에 두어 맥과 폰이 함께 쓴다.
- **한국어 조사는 떼지 않는다.** 낱말로 나누면 진단의 사례(`로그 밑`, `병렬 저항`, `로그 법칙`)가 풀린다. 조사를 잘못 떼면 다른 말을 찾는다.
- **명령줄 `Jindesk search`.** 화면 없이 실제 데이터로 순위를 보고 진단 질의를 다시 잰다. 앱 캐시의 색인을 건드리지 않게 따로 만든 색인을 쓴다.
- **폰의 본문 찾기는 다음 PR 이다.** 같은 색인을 폰도 빌드해 받은 데이터로 기기 안에서 만든다. 원래 자료의 글자층(1,305쪽에 0.5MB)도 받아 쪽까지 찾는다.
- 색인은 캐시라 데이터 스펙이 바뀌지 않는다. 그래서 스키마 판을 올리지 않는다. 색인 판만 3 에서 4 로 올려 다시 만든다.
