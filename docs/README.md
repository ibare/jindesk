# Jindesk 설계 문서

Jindesk 는 IB 과정(MYP 10, DP 1·2)을 공부하는 학생 한 명을 위한 Mac 앱이다. 학교에서 받은 PDF, PPT, 판서 사진을 격리된 headless Claude Code 로 읽어 강의 계획 항목마다 개념을 정리하고, 과목에 맞는 수식·그래프·실험·회로·분자 그림으로 펼쳐 보인다. 학습 내용은 영어가 원문이고, 한국어 번역은 문단마다 곁에서 펼쳐 본다.

작업 실행 방식은 설계안 검토 앱 Assayer 에서 가져온다. Assayer 는 따로 있는 앱이고, 이 저장소는 그 코드를 쓰지 않고 필요한 부분을 옮겨 와 고친다(`ARCHITECTURE.md`의 "Assayer 에서 가져오는 것").

이 저장소는 공개다. 학생의 자료, 기록, 이름, 학교 이름을 넣지 않는다. 학생의 데이터는 학생 맥의 데이터 폴더에만 있다.

## 사람

- **학생**: 앱을 쓰는 사람. 자기 맥에서 자료를 넣고, 읽고, 코멘트와 요구를 남긴다. git 과 GitHub 을 쓰지 않는다.
- **관리자(아빠)**: 앱을 만들고 고치는 사람. 자기 맥에서 지침과 코드를 고치고, 이 리포의 GitHub Releases 로 새 판을 낸다. 학생 맥의 앱은 그 릴리즈를 보고 스스로 업데이트한다.

## 한 줄씩

- 결정적인 일(입력 고정, 검증, 배치, 계산)은 러너 코드가, 판단(읽기, 설명, 번역)은 에이전트가 한다.
- 파일이 원본이다. 사람이 읽는 파일은 YAML, 기계가 덧붙이는 파일은 JSONL, 작은 기록은 JSON 이다. SQLite 는 다시 만들 수 있는 색인으로만 쓴다.
- 과목·학년·수준은 미리 등록하지 않는다. 자료를 넣을 때 꼬리표로 붙이고, 강의 계획 목차는 따로 만드는 작업이 있다.
- 글은 출처와 여러 검사로 엄밀하게 확인한다. 그림과 인터랙션은 에이전트가 코드로 직접 짜고, 러너는 돌아가는지만 본다. 글이 바르면 이상한 그림은 학생이 알아챈다.
- 페이지는 id 가 있는 단위로 이루어지고, 단위마다 판과 어디서 왔는지의 해시가 있다. 바뀐 곳과 그 아래 층만 다시 만든다.
- "더 쉽게", "더 자세히" 같은 요구는 데이터로 남아 나중에 다시 만들 때도 적용된다.
- git 은 쓰지 않는다. 백업은 데이터 폴더를 통째로 한다.
- 앱은 GitHub Releases 를 보고 작업이 없을 때 스스로 업데이트한다.
- 데이터 모양이 바뀌면 사본에서 마이그레이션하고 검증한 뒤 바꿔 끼운다. 학생이 쓴 글은 에이전트에 통과시키지 않는다.
