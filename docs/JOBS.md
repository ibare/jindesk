# 작업

작업 종류마다 `jobs/<종류>/INSTRUCTIONS.md` 하나가 그 작업 에이전트의 지침이다. 러너가 시스템 프롬프트로 넣는다. 지침을 바꾸면 파일 위의 버전을 올린다. 기록에는 지침 버전, 커밋, 미커밋 여부(`dirty`)가 남는다.

| 종류 | id | 에이전트 | 웹 |
|---|---|---|---|
| 목차 만들기 | `syllabus-build` | 하나 | 없음 |
| 자료 넣기 | `source-intake` | 없음 (러너만) | — |
| 자료 읽기 | `source-reading` | 1차·2차 + 학생 독자 | 없음 |
| 개념 정리 | `concept-curation` | 하나 + 학생 독자 | 없음 |
| 학습 페이지 만들기 | `page-build` | 개념마다 하나, 셋씩 | 없음 |
| 번역 | `translation` | 개념마다 하나, 셋씩 | 없음 |
| 관점 붙이기 | `facets` | 개념 여덟 개씩, 셋씩 | 레퍼런스 찾기만 |
| 물어보기 | `ask` | 하나 | 없음 |
| 부분 다시 만들기 | `regen` | 방식에 따라 (`REGENERATION.md`) | 없음 |
| 확인 문제 | `practice` | 하나 | 없음 |
| 마이그레이션 | `migration` | 의미 변경이 있을 때만 (`MIGRATION.md`) | 없음 |

## 대기열

| 대기열 | 작업 | 함께 도는 수 | 까닭 |
|---|---|---|---|
| 자료 | 자료 넣기, 자료 읽기 | 2 | 자료마다 서로 상관없다 |
| 정리 | 목차 만들기, 개념 정리 | 1, 차례로 | 정리층의 내용을 정하는 일이라, 둘이 같은 사본으로 함께 돌면 서로 덮어쓴다 (Assayer 의 카탈로그 정리와 같다) |
| 페이지 | 학습 페이지 만들기, 번역, 관점 붙이기 | 작업 1, 그 안에서 에이전트 셋 | 개념마다 서로 상관없다. 쓰기 직전에 원문 해시를 다시 본다 |
| 대화 | 물어보기, 부분 다시 만들기 | 2, 같은 개념은 차례로 | 학생이 기다린다. 다른 대기열보다 먼저 자리를 준다 |
| 마이그레이션 | 마이그레이션 | 단독 | 다른 대기열을 모두 멈춘다 |

**뒤따르는 작업.** 작업은 끝나면 자기 산출물에 필요한 다음 작업을 대기열에 넣는다. 이 흐름은 Assayer 에서 설계 검토가 기술 추출을 뒤따라 넣는 것과 같다. 다음 작업은 입력을 요청할 때가 아니라 시작할 때 다시 고른다. 그사이 다른 작업이 이미 처리해 할 일이 없으면 실패 없이 끝난다.

```
자료 넣기 → 자료 읽기 → 개념 정리 → 학습 페이지 만들기 → 번역
                                                         └→ 관점 붙이기 (새 개념일 때)
근거 문서로 표시한 자료 넣기 → 목차 만들기
```

## 공통 검사

모든 작업의 러너 검사에 함께 들어가는 것이다.
- 출력이 그 작업의 JSON 스키마에 맞는지 본다.
- 한자, 일본어, 금지어(`meta/privacy.yaml`)가 없는지 본다.
- 학습 내용(영어 칸)이 영어인지 본다. 한글이 섞이면 실패다. 한국어 칸은 한국어여야 한다.
- 출처로 단 쪽이 그 자료에 있는지 본다. 이벤트 기록에서 그 쪽의 글자층이나 이미지를 Read 한 적이 있는지도 본다. 출처는 Assayer PR 리뷰의 `coverage.json`처럼 센다.
- 틀리면 같은 세션을 이어 한 번 고쳐 쓰게 한다. 그래도 틀리면 그 대상만 넣지 않고 기록에 남긴다.

**학생 독자 시험.** Assayer 의 격리 시험을 학생 독자로 바꾼 것이다.
- 독자는 도구, 작업 공간, 세션이 없다. 본문만 받는다.
- 독자 수준(MYP 10, DP SL, DP HL)은 요청이 정한다.
- 원래 자료 없이 이해되는지를 단위마다 판정한다.
- 기계 검사도 함께 한다. "slide 3", "see the diagram above", "as shown on the worksheet"처럼 원래 자료가 있어야만 통하는 말을 찾는다.

## 목차 만들기 (`syllabus-build`)

- **입력.** 과목과 근거 문서다. 근거 문서는 자료 넣기에서 "목차의 근거"로 표시한 과목 가이드, 공개 과목 요약, 선생님의 과정·단원 안내다. MYP 는 단원 안내(unit plan)다.
- **준비.**
  - 근거 문서의 글자층과 쪽 이미지
  - 지금 목차
  - 이미 쓰인 항목 코드 목록: 엔트리와 개념이 가리키는 것
  - 목차 밖 개념 목록: 보강할 때 넣는다
- **실행.** 에이전트 하나가 `out/syllabus.json`을 쓴다. 항목 나무를 만들고, 항목마다 코드, 영어 제목, 수준(SL+HL, HL), 출처 쪽을 단다. MYP 는 단원 하나가 항목 하나이고, 핵심 개념·관련 개념·글로벌 맥락·탐구 진술을 함께 뽑는다.
- **러너 검사.**
  - 코드가 겹치지 않는다.
  - 상위·하위 구조가 맞다 (A > A.1).
  - 수준 값이 정해진 값이다.
  - 항목마다 출처 쪽이 있다.
  - 이미 쓰인 코드가 사라지지 않는다. 이름이 바뀌었으면 `renamed_from`이 있어야 한다.
- **반영.** `syllabus/<과목 id>.yaml`에 쓴다. 처음 만든 목차는 "확인 필요"로 두고, 관리자가 화면에서 확인한다.
- **보강.** 목차 밖 개념을 받아 넣을 항목이 생겼는지 본다. 넣을 수 있으면 개념 정리가 그 개념을 옮긴다.

## 자료 넣기 (`source-intake`)

러너만 한다.

- **입력.** 파일들, 과목, 메모(적지 않아도 된다), "목차의 근거" 표시. 강의 계획 항목은 고르지 않는다.
- **빼는 것.** 원본 바이트 해시가 이미 있는 자료는 뺀다. 크기 상한(설정, 기본 100MB)을 넘는 자료도 뺀다. 같은 시트에 같은 내용이 두 번 있으면 하나만 둔다. 뺀 자료는 까닭과 함께 보인다.
- **바꾸기.**
  - PPT, PPTX, KEY: Keynote(AppleScript 로 열어 PDF 내보내기)로 PDF 로 바꾼다. Keynote 가 없으면 LibreOffice(`soffice --headless --convert-to pdf`)를 쓴다.
  - DOCX: Pages 나 LibreOffice 로 바꾼다.
  - HEIC: JPEG 로 바꾼다.
  - PDF, JPEG, PNG: 그대로 둔다.
- **쪽 나누기.**
  - PDFKit 으로 쪽마다 글자층을 뽑는다.
  - 글자가 거의 없는 쪽(스캔, 사진, 판서)은 Vision 글자 인식으로 대략의 글자층을 만들고, 그렇게 만들었다고 표시한다. 뜻은 에이전트가 쪽 이미지를 보고 읽는다.
  - 쪽 이미지(긴 변 1600px PNG)는 캐시에 둔다.
- **`index.md`.** 쪽 번호, 글자 수, 글자층을 만든 방법, 그림이 많은 쪽을 적는다. 에이전트가 먼저 읽는다.
- **뒤따름.** 자료 읽기를 넣는다. "목차의 근거"로 표시했으면 목차 만들기를 넣는다.

## 자료 읽기 (`source-reading`)

Assayer 의 설계안 검토와 같은 모양이다.

- **입력.** 자료 하나.
- **준비.** `input/`에 다음을 둔다.
  - `request.md`: 과목, 과정, 수준, 메모
  - `index.md`, 쪽마다 글자층과 쪽 이미지
  - 이 과목의 목차
  - 정리된 개념 목록 (id 와 제목만)
  - 용어 어휘
- **1차.** 자료 요약 초안과 엔트리 초안을 쓴다. 끝나면 러너가 초안을 `input/first-pass/`로 넘긴다. 1차의 작업 메모는 2차가 보지 못하게 `work/<작업 id>/pass1/`로 옮긴다.
- **2차.** 새 에이전트가 먼저 혼자 읽은 뒤 1차를 반박·보완한다. 최종 자료 요약(`out/report.md`)과 엔트리(`out/entries/*.json`)를 쓴다.
- **엔트리.** 영어로 쓴다.
  - 제목
  - 항목 코드 제안
  - 본문
  - 주장과 출처 쪽, 조건
  - 기호
  - 자료에 있는 예시와 흔한 오해
- **러너 검사.**
  - 공통 검사를 한다.
  - 읽지 않은 쪽이 있으면 경고하고 리포트 끝에 적는다.
  - 항목 코드가 목차에 없으면 실패가 아니다. 그 엔트리를 "목차 밖"으로 둔다.
  - 엔트리 본문으로 학생 독자 시험(자료의 수준)을 한다. 실패한 엔트리는 2차 세션을 이어 한 번 고쳐 쓰고, 그래도 실패하면 넣지 않는다.
- **반영.** `library/entries/<과목>/<항목>/<slug>.md`에 쓴다. 같은 경로가 있으면 `<slug>--<작업 id>.md`로 나란히 둔다. 기록은 `records/source-reading/<작업 id>/`에 둔다.
- **뒤따름.** 개념 정리.

## 개념 정리 (`concept-curation`)

Assayer 의 카탈로그 정리와 같은 모양이다.

- **입력.**
  - 아직 개념에 들어가지 않은 엔트리. 과목·항목별로 나눠 한 건에 열 개 안팎이다.
  - 그 항목들의 기존 개념, 목차, 용어 어휘
- **실행.** 에이전트 하나가 같은 개념의 엔트리를 묶어 개념 원문을 새로 쓰거나 기존 개념을 보강한다.
  - 원문은 단위(`units`)로 쓰고, 단위마다 글, 조건, 주장과 출처를 둔다.
  - 선수 개념과 과목 사이 연결도 쓴다.
  - 결정은 `out/plan.json`에 남긴다.
- **러너 검사.**
  - 입력 엔트리가 빠짐없이 한 곳(개념 또는 보류)에 들어갔다.
  - 원문 단위의 출처는 그 엔트리들의 출처 안에 있다. 정리가 새 출처를 만들지 못한다.
  - 기존 단위를 보강할 때 원래 주장이 빠지지 않았다. 빠졌으면 까닭이 있어야 한다.
  - 선수 개념이 있는 개념 id 다. 아직 없는 개념이면 그렇다고 표시해야 한다.
  - 기호표가 페이지 안에서 일관된다.
  - 새로 쓰거나 바뀐 단위로 학생 독자 시험을 한다.
- **반영.** `concept.yaml`에 쓴다.
  - 기존 단위는 id 를 그대로 두고, 새 단위에 새 id 를 붙인다.
  - 출현 목록은 러너가 계산한다.
  - 여러 개념을 함께 바꾸면 `apply.json`을 먼저 쓴다.
  - 기록은 `records/concept-curation/<작업 id>/`에 둔다.
- **뒤따름.** 바뀐 개념의 학습 페이지 만들기.

## 학습 페이지 만들기 (`page-build`)

Assayer 의 패턴 시각화와 같은 자리다. 원문이 기준이고 페이지는 읽기 위한 판이다.

- **입력.**
  - 개념의 `concept.yaml`과 지금 `page.yaml`
  - 그 개념의 살아 있는 요구(`directives.jsonl`)
  - 글 블록 스키마, 블록 틀과 공통 부품 설명, 기호표, 용어 어휘
- **대상 단위.** 처음이면 전부다. 다음부터는 낡은 단위만 한다. 낡은 단위는 `from`의 원문 해시가 다르거나 지침 판이 바뀐 것이다. 나머지 단위는 건드리지 않는다.
- **실행.** 개념마다 에이전트 하나가 `out/page.json`을 쓴다.
  - 원문 단위 하나에서 문단 단위 하나와, 필요하면 블록·강조 상자·확인 문제를 만든다.
  - 그림 블록의 코드는 `out/figures/<이름>.html`에 따로 쓰고 `page.json`에서 이름으로 가리킨다.
  - 문단 단위의 글은 원문 단위의 글을 그대로 쓴다. 요구로 다시 만든 판만 다를 수 있다(`REGENERATION.md`).
- **러너 검사.**
  - 공통 검사를 한다.
  - 글 블록은 스키마를 보고 계산으로 확인한다(`PAGES.md`의 글 블록). 수식은 앱 번들의 KaTeX 를 JavaScriptCore 로 돌려 파싱한다.
  - 그림 블록은 돌아가는지만 본다(`PAGES.md`의 그림 블록).
  - 원문 단위가 빠짐없이 어느 페이지 단위의 `from`에 있다.
  - 문단 글이 원문과 같다.
  - 요구가 적용된 단위에는 그 요구가 남아 있다.
- **반영.** `page.yaml`에 쓴다. id 는 그대로 두고 판을 올리며, 이전 판은 `history.jsonl`에 덧붙인다. 그림 코드는 개념 폴더의 `figures/`로 옮기고, 그 그림이 쓰는 라이브러리는 `library/vendor/`에 받아 둔다. 쓰기 직전에 `concept.yaml` 해시를 다시 본다.
- **뒤따름.** 바뀐 단위의 번역. 새 개념이면 관점 붙이기도 넣는다.

## 번역 (`translation`)

- **입력.**
  - 대상: 곁 층이 없거나 낡은 영어 단위. 쉽게·자세히 곁 층의 영어 글도 대상이다.
  - 맥락: 이웃 단위(읽기만), 용어 어휘, 기호표
- **실행.** 개념마다 에이전트 하나가 `out/layers.json`을 쓴다. 어휘에 없는 용어는 한국어와 함께 제안한다.
- **러너 검사.**
  - 공통 검사를 한다.
  - 대상 단위마다 번역이 하나씩 있다.
  - 숫자, 단위, 수식, 기호가 영어와 같다. 기계로 뽑아 개수까지 견준다.
  - 어휘에 있는 영어 용어가 나오는 단위에는 정해진 한국어가 들어갔다.
  - 영어 문장이 남지 않았다. 용어를 괄호로 함께 쓰는 것은 된다.
  - 길이 비율이 범위 안이다.
- **새 용어.** 어휘에 없던 용어는 다른 표기와 맞춰 본다. 대소문자, 띄어쓰기, 줄표를 가리지 않는다. 있으면 그 용어의 다른 이름으로 넣고, 없으면 새 용어로 `glossary.yaml`에 더한다. Assayer 기술 어휘의 이름 맞추기와 같다.
- **반영.** `layers.yaml`의 한국어 층에 쓴다. 어느 단위의 몇 판에서 만들었는지(`from`)와 그 단위의 해시를 함께 둔다.

## 관점 붙이기 (`facets`)

Assayer 의 기술 추출과 같은 모양이다. 관점은 고정이고, 값은 어휘로 맞춘다.

| 관점 | 값 |
|---|---|
| 강의 계획 항목, 수준 | 러너가 채운다 |
| 명령어 (command terms) | IB 명령어 목록 (고정) |
| 핵심 개념 | MYP 핵심 개념 16개, DP 과목별 개념 목록 (고정) |
| 관련 개념 | 과목별 어휘 |
| 글로벌 맥락 | MYP 글로벌 맥락 6개 (고정) |
| NOS | 과학 과목의 과학의 본성 주제 |
| TOK | 지식 영역 |

- **실행.** 개념 여덟 개씩 에이전트가 관점을 붙인다(웹 없음).
- **레퍼런스 찾기.** 아직 레퍼런스를 찾지 않은 개념을 열두 개씩 묶어 새 에이전트가 대표 자료를 셋까지 찾는다. 웹 도구를 쓰는 곳은 여기뿐이다. 러너는 공개된 https 주소이면서 그 에이전트의 이벤트 기록에서 WebFetch 가 성공한 주소만 받는다. 찾지 못한 개념은 빈 목록으로 두고 찾은 작업을 남겨 다시 찾지 않는다.
- **러너 검사.** 공통 검사, 관점 값이 어휘에 있는지, 개수 범위를 본다.
- **반영.** `facets.yaml`, `references.yaml`에 쓴다.

## 물어보기 (`ask`)

- **입력.**
  - 질문 코멘트
  - 그 개념 폴더와, 그 개념이 나온 자료의 글자층·쪽 이미지
  - 용어 어휘
- **실행.** 에이전트 하나가 `out/answer.json`을 쓴다. 답은 영어로 쓰고, 한국어 번역, 출처 쪽, 보충 표시를 함께 둔다.
- **러너 검사.**
  - 공통 검사를 한다.
  - 영어 답과 한국어 답의 숫자·기호가 같다.
  - 자료 밖 설명은 보충으로 표시됐다.
- **이 개념 밖의 질문.** 웹을 찾지 않고 "이 페이지의 자료로는 답할 수 없다"고 답한다. 관련 개념이 있으면 함께 보인다.
- **반영.** `comments.jsonl`에 답글 줄을 덧붙인다. 기록은 `records/ask/<작업 id>/`에 둔다.

## 확인 문제 (`practice`)

4단계에 만든다.
- 명령어로 문제를 내고, 자료를 근거로 채점 기준을 쓴다.
- 러너가 답을 계산으로 확인하고, 채점 기준의 출처를 대조한다.
- 학생이 푼 기록(`learner/practice/`)으로 다시 볼 개념을 고른다.
