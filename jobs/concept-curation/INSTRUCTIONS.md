# 개념 정리 지침

지침 버전: `0.10`

이 문서는 개념 정리 에이전트가 따르는 유일한 지침이다. 에이전트는 자료 묶음 하나를 읽은 결과인 엔트리들을 같은 개념끼리 묶어, 개념마다 원문을 쓴다. 묶음은 학생이 같은 내용을 다룬다고 묶어 넣은 자료들이다. 원문은 단위(unit)로 나뉘고, 학습 페이지의 문단이 단위의 글을 그대로 쓴다. 그래서 단위의 글은 학생이 그대로 읽고 배우는 설명이다. 외국어를 배우는 과목이면 10장이 앞의 장보다 먼저다. 사람이 고른 개념을 다시 정리하는 작업이면 11장도 따른다.

## 1. 원칙

1. **출처가 있는 것만 주장한다.** 단위의 주장(claims)은 엔트리들의 주장과 이미 있는 개념의 주장에서 온다. 출처(`src`)는 거기 있는 것(`<자료 id>#p<쪽>`)을 그대로 옮긴다. 정리가 새 출처를 만들지 못한다. 러너가 대조한다.
2. **엔트리를 빠짐없이 둔다.** 정리할 엔트리(`e01` …)마다 개념에 넣거나, 개념이 될 수 없으면 보류(`held`)에 까닭과 함께 둔다. 큰 엔트리는 여러 개념이 나눠 쓸 수 있다. 그 엔트리를 쓰는 개념마다 `entries`에 넣고, 주장을 나눠 갖는다. 엔트리의 주장은 그 엔트리를 쓰는 개념들 가운데 어딘가에 남아야 한다. 보류와 개념에 함께 두지는 않는다.
3. **같은 개념은 하나로, 다른 개념은 따로.** 자료가 달라도 같은 개념이면 한 개념으로 묶는다. 이미 있는 개념(`input/concepts/`)과 같으면 새로 만들지 않고 그 개념을 보강한다. 다른 질문에 답하는 것은 따로 둔다(3장의 개념의 크기).
4. **과목 전체에서 보충할 곳을 찾는다.** 묶음은 주제 하나의 경계가 아니다. 묶음에 다른 단원의 내용(워크시트 끝의 지난 단원 복습 같은 것)이 섞여 있으면, 그 단원의 이미 있는 개념을 보강한다. 풀이가 있는 복습 문제는 그 개념의 예제 단위가 된다. 맞는 개념이 없으면 새 개념을 만든다. 나중에 그 주제의 자료가 들어오면 그때의 정리가 이 개념을 보강한다.
5. **보류된 엔트리를 다시 본다.** `input/held/`의 엔트리(`h01` …)는 지난 정리나 자료 읽기가 보류한 것이다. 까닭과 함께 받는다. 이번 정리로 맞는 개념이 생기거나 이미 있는 개념에 보충할 수 있으면 그 개념의 `entries`에 넣고 내용을 단위로 옮긴다. 맞는 곳이 없으면 아무 데도 적지 않는다. 그러면 계속 보류로 남는다.
6. **영어로 쓴다.** 제목, 단위의 글, 조건, 주장, 기호의 뜻, 항목 제안이 모두 영어다. 한글, 한자, 일본어를 섞지 않는다. 기록(`out/report.md`)과 보류 까닭만 한국어다.
7. **원래 자료 없이 읽혀야 한다.** "slide 3", "see the diagram above", "as shown on the worksheet" 같은 말을 쓰지 않는다.
8. **평가 과제의 답은 쓰지 않는다.** 엔트리에 평가 과제의 답이나 풀이가 섞여 있으면 옮기지 않는다.
9. **자료가 밝힌 학습 목표를 해낼 수 있게 쓴다.** `input/request.md`의 "학습 목표"는 선생님이 이 수업에서 학생이 할 수 있게 되기를 적어 둔 것이다. 개념이 그 목표에 해당하면, 학생이 개념의 글만 읽고 그 목표를 해낼 수 있어야 한다. 목표가 해석(interpret), 비교(compare), 추론(make inferences), 설명(explain)을 요구하면 계산 절차만 쓰지 않고, 결과가 무엇을 뜻하는지, 왜 그런지, 자료가 바뀌면 어떻게 되는지를 쓴다. 수준은 자료를 따른다: 새 개념이나 공식을 더하지 않고, 자료가 다루는 내용을 설명한다. 자료에 없는 설명은 4장대로 보충 단위로 둔다. 목표가 여러 개념을 묶어 말하면(여러 통계값을 나열하거나 분류·계산·적용을 함께 말하는 목표) 이 개념이 맡는 부분만 해낼 수 있게 쓴다. 다른 개념이 맡는 내용을 이 개념에 다시 쓰지 않고, 필요하면 선수 개념이나 연결로 가리킨다(개념 하나는 질문 하나, 3장).
10. **질문하지 않는다.** 무인으로 돈다. 판단이 갈리면 가장 그럴듯한 쪽을 고르고 기록에 적는다.

## 2. 작업 공간

```
input/request.md         과목, 학년·수준, 묶음, 정리할 엔트리 표(키 e01 …), 보류된 엔트리 표(키 h01 …, 까닭), 이미 있는 개념 표(키 k01 …), 자료가 밝힌 학습 목표
input/entries/e01.md     정리할 엔트리 (머리말 YAML + 영어 본문). 주장마다 src 가 있다
input/held/h01.md        보류된 엔트리. 모양은 entries 와 같다
input/concepts/k01.yaml  이미 있는 개념의 원문 (단위 id, 글, 주장, 출처)
input/syllabus.yaml      강의 계획 목차 (있을 때만)
input/glossary.yaml      용어 어휘 (아직 없으면 terms 가 비어 있다)
out/                     여기에만 쓴다
work/                    작업 메모
```

## 3. 개념의 크기

개념 하나는 학습 페이지 하나다. 학생이 "이것을 찾아보자" 할 때의 단위다.

- **개념 하나는 질문 하나에 답한다.** "로그란 무엇인가", "로그의 성질은 무엇이고 왜 성립하는가", "로그방정식은 어떻게 푸는가", "그래프로 지수방정식을 어떻게 푸는가"는 서로 다른 개념이다.
- **정의와 그 쓰임은 대개 다른 개념이다.** 정의(로그의 뜻, 지수 꼴과 로그 꼴)와 그것을 쓰는 방법(값 구하기, 방정식 풀기)을 한 개념에 몰지 않는다. 쓰임 쪽 개념에서는 정의를 한두 문장으로 떠올리게만 한다.
- **엔트리의 제목은 실마리다.** 자료 읽기가 따로 쓴 엔트리는 대개 따로 개념이 된다. 이름이 같은 엔트리(여러 자료의 같은 주제)는 한 개념이다. 엔트리 하나가 여러 질문에 답할 만큼 크면(슬라이드 수십 쪽에 걸친 것) 나눠 여러 개념에 쓴다.
- **단위가 여덟 개를 넘으면 나눌지 따진다.** 나눌 곳이 있으면 나눈다.
- **이미 있는 개념이 너무 커졌으면 나눈다.** 옮길 단위를 그 개념의 `removed_units`에 `"<새 개념 slug> 로 옮김"`이라는 까닭과 함께 적고, 새 개념의 `units`에 `id`를 `null`로 해서 넣는다. 옮긴 단위는 원래 출처를 그대로 쓴다.

## 4. 단위 쓰기

단위 하나는 학습 페이지의 문단 하나다.

- **한 단위에 생각 하나.** 정의, 규칙 하나와 그 까닭, 방법 한 단계 묶음, 풀이한 예제 하나처럼 한 문단으로 설명되는 것이다.
- **가르치는 차례로 둔다.** 무엇인지 → 왜 그런지 → 어떻게 쓰는지 → 예제 → 주의할 점.
- **학생 수준에 맞춘다.** `input/request.md`의 학년·수준(예: MYP 5 Extended, DP1 HL)인 학생이 혼자 읽고 이해할 수 있게 쓴다. 자료가 쓴 용어와 기호를 따른다. IB 명령어(command terms)는 그대로 쓴다.
- **자료의 설명을 살린다.** 엔트리의 본문, 예제, 흔한 오해를 단위로 옮긴다. 예제는 엔트리에 풀이까지 있는 것만 단위로 쓴다. 엔트리의 예제에는 출처(`src`)가 있다. 예제를 단위로 옮기면 그 출처를 그 단위의 주장으로 단다(주장의 글은 예제의 결과나 핵심 줄). 그래야 학습 페이지에 근거 쪽이 나온다.
- **연결하는 말은 써도 된다.** 단위와 단위를 잇는 한두 문장은 써도 된다. 다만 그런 말은 주장으로 넣지 않는다.
- **자료에 없는 설명은 따로 둔다.** 학생이 이해하려면 꼭 필요한데 엔트리(자료)에 없는 정의, 규칙, 까닭을 더할 때는 그 설명만 따로 단위로 두고 주장을 달지 않는다. 주장이 하나도 없는 단위는 화면에 "보충"으로 보이고, 주장이 있는 단위는 "자료"로 보인다. 자료에서 온 단위 안에 자료에 없는 정의나 규칙을 섞지 않는다.
- **수식은 TeX.** 글 속 수식은 `\( … \)`, 따로 선 수식은 `\[ … \]`다. `$`는 쓰지 않는다. KaTeX 가 그리는 명령만 쓴다. JSON 안이므로 역슬래시는 두 번 쓴다.
- **글 모양.** 문단 사이는 빈 줄이다. 핵심 용어에 `**굵게**`, 나열에 `- `를 써도 된다. 그 밖의 마크다운(제목, 표, 링크)은 쓰지 않는다.

## 5. 선수 개념과 과목 사이 연결

- **선수 개념(`prerequisites`).** 이 개념을 배우기 전에 알아야 하는 개념이다. 이미 있는 개념이면 키(`k01`), 이번에 새로 만드는 개념이면 `"new:<slug>"`, 아직 어디에도 없는 개념이면 `"missing:<영어 제목>"`으로 적는다. 바로 앞의 것만 적는다(대개 하나나 둘).
- **과목 사이 연결(`links`).** `input/request.md`의 "다른 과목의 개념" 가운데 같은 생각을 다른 과목에서 다루는 개념이 있으면 `{ "concept": "<그 개념 id>", "note": "<관계 한 문장, 영어>" }`로 적는다. 예: 수학의 지수 함수 ↔ 화학의 반감기. 억지로 찾지 않는다. 없으면 빈 목록이다.

## 6. 이미 있는 개념 보강

이미 있는 개념에 새 엔트리를 넣을 때:

- 기존 단위는 `id`를 그대로 둔다. 글을 그대로 두려면 글을 그대로 옮긴다. 새 엔트리가 더 나은 설명이나 조건을 주면 고쳐 쓴다. 원래 주장은 빼지 않는다.
- 새 내용은 `id`를 `null`로 둔 새 단위로 넣는다. 러너가 id 를 붙인다.
- 기존 단위를 빼야 하면(다른 단위와 합쳤거나 틀린 것으로 드러났을 때) `removed_units`에 `id`와 까닭을 적는다. 까닭 없이 빠진 단위가 있으면 러너 검사에서 틀린다.

## 7. `out/plan.json`

```json
{
  "concepts": [
    {
      "concept": null,
      "slug": "laws-of-logarithms",
      "title": "Laws of logarithms",
      "item": "Exponents and logarithms",
      "entries": ["e01", "e03"],
      "symbols": [{ "symbol": "a", "meaning": "the base of the logarithm" }],
      "prerequisites": ["new:definition-of-a-logarithm"],
      "links": [],
      "units": [
        {
          "id": null,
          "text": "A logarithm answers the question \"what power?\". If \\(a^y = x\\), then \\(\\log_a x = y\\) ...",
          "conditions": ["\\(a > 0\\), \\(a \\neq 1\\)"],
          "claims": [{ "text": "\\(\\log_a x = y\\) means \\(a^y = x\\)", "src": ["20261017-3fa2c1d0#p3"] }]
        }
      ],
      "removed_units": []
    },
    {
      "concept": "k02",
      "title": "Change of base",
      "entries": ["e02"],
      "units": [
        { "id": "u1", "text": "…기존 글 그대로…", "conditions": [], "claims": [{ "text": "…", "src": ["20261010-77ab01cd#p8"] }] },
        { "id": null, "text": "…새 단위…", "conditions": [], "claims": [{ "text": "…", "src": ["20261017-3fa2c1d0#p9"] }] }
      ],
      "removed_units": []
    }
  ],
  "held": [{ "entry": "e05", "reason": "표지 쪽의 수업 목표만 있어 개념이 아니다" }]
}
```

| 필드 | 무엇 |
|---|---|
| `concept` | 보강하는 기존 개념의 키(`k01`). 새 개념이면 `null` |
| `slug` | 새 개념의 이름(영어 소문자, 숫자, `-`). 기존 개념이면 쓰지 않아도 된다 |
| `title` | 개념 이름 |
| `item` | 목차가 있으면 항목 코드. 없으면 단원이나 주제의 짧은 영어 이름. 같은 단원의 다른 개념과 같은 이름을 쓴다 |
| `entries` | 이 개념에 넣는 엔트리 키. 엔트리 하나를 여러 개념이 나눠 쓰면 그 개념마다 넣는다. 보류된 엔트리를 붙이면 그 키(`h01`)도 넣는다 |
| `symbols` | 이 개념에서 쓰는 기호와 뜻 (단위가 있으면 `unit`) |
| `prerequisites` | 먼저 알아야 할 개념 (5장) |
| `links` | 다른 과목의 같은 생각 (5장) |
| `units` | 단위들. 가르치는 차례 |
| `removed_units` | 기존 개념에서 빼는 단위와 까닭 |
| `units[].from` | 다시 정리(11장)에서만: 이 단위가 담은 고른 개념의 옛 단위 (`"k03.u2"`) |
| `retired` | 다시 정리(11장)에서만: 없애는 고른 개념 |
| `held` | 개념이 될 수 없는 정리할 엔트리(`e01`)와 까닭(한국어). 보류된 엔트리(`h01`)는 적지 않는다 |

## 8. `out/report.md`

한국어로 짧게 쓴다. 어떤 엔트리를 어느 개념에 넣었는지, 새로 만든 개념과 보강한 개념, 나눈 개념, 다른 단원의 개념에 보충한 것, 보류한 엔트리와 까닭, 보류에서 풀어 붙인 엔트리, 판단이 갈린 곳.

## 9. 러너 검사

틀리면 같은 세션에서 문제 목록을 받고 한 번 고쳐 쓴다. 그래도 틀리면 이번 정리는 반영하지 않는다.

- 정리할 엔트리가 빠짐없이 개념이나 보류에 들어갔다. 보류와 개념에 함께 들어가지 않았다.
- 엔트리의 주장이 그 엔트리를 쓰는 개념들의 단위 어딘가에 출처로 남았다. 빠졌으면 한 번 고쳐 쓰고, 그래도 남으면 기록에 남는다.
- 단위의 출처가 그 개념에 넣은 엔트리(보류에서 붙인 것 포함)나 이미 있는 개념의 출처 안에 있다.
- 기존 단위가 까닭 없이 빠지지 않았다.
- 영어 칸에 한글, 한자, 일본어가 없다. 원래 자료가 있어야만 통하는 말이 없다.
- 모든 수식이 KaTeX 로 파싱된다.
- **학생 독자 시험.** 새로 쓰거나 바뀐 단위를 그 학년·수준의 학생이 글만 읽고 이해하는지, 도구 없는 다른 에이전트가 판정한다. 실패하면 학생이 알 수 없었던 것과 함께 받아 한 번 고쳐 쓴다.
- **학습 목표 시험.** 새로 쓰거나 바뀐 개념마다, 그 개념이 나온 자료의 학습 목표를 받은 판정자가 목표마다 이 개념에 해당하는지, 이 개념의 글만 읽고 해낼 수 있는지 본다. 해당하는데 해낼 수 없으면 빠진 것과 함께 받아 한 번 고쳐 쓴다(보충 단위를 더하거나 단위를 고친다). 학생 독자 시험과 같은 차례에 함께 받는다.

## 10. 언어 습득 과목

`input/request.md`에 "과목 갈래: 언어 습득"이 있으면 학생이 목표 언어(예: Spanish)를 배우는 과목이다. 이 장이 앞의 장과 다르면 이 장을 따른다.

1. **개념은 언어 단위다.** 개념 하나는 문법 요점, 낱말 세트, 표현 묶음, 글 종류 가운데 하나다(자료 읽기 지침과 같은 갈래). 3장의 "질문 하나"는 이렇게 읽는다: 이 형태는 어떻게 만들고 언제 쓰는가(문법 요점), 이 상황에서 어떤 낱말을 쓰는가(낱말 세트), 이것을 어떻게 말하는가(표현 묶음), 이 글은 어떻게 쓰는가(글 종류). 단원 주제("Talking about the environment")는 개념이 되지 않는다. 같은 문법이나 표현이 여러 단원의 자료에 나오면 한 개념에 모으고, 단원마다 따로 설명하지 않는다.
2. **주제는 예문의 배경이다.** 단위의 글은 목표 언어를 쓰는 법을 설명한다. 주제에 대한 사실, 사회적 설명, 통계는 쓰지 않는다. 엔트리에 그런 주장이 있으면 단위의 글로 옮기지 않고, 같은 쪽의 낱말, 표현, 예문으로 쓴다. 예문은 단원 주제에서 고른다.
3. **단원 틀은 보류한다.** 제목이 `Unit frame:`으로 시작하는 엔트리, 또는 단원의 틀(탐구 진술, 핵심·관련 개념, 글로벌 맥락, ATL, 학습자상, SDG, 수업 활동 방법)만 담은 엔트리는 개념에 넣지 않고 `held`에 "단원 틀: 언어 습득 과목은 단원 틀을 개념으로 만들지 않는다"로 둔다. 보류된 엔트리(`h01` …) 가운데 단원 틀은 붙이지 않는다. 그 단원 이름과 주제는 예문을 고를 때 참고한다.
4. **학습 목표는 목표 언어로 해내는 것이다.** 1장의 9 를 이렇게 읽는다. "Explain", "Describe", "Talk about", "Give opinions" 같은 목표는 주제를 목표 언어로 말하고 쓰는 일이다. 학생이 개념의 글만 읽고 그것을 목표 언어로 해낼 수 있게 필요한 형태, 낱말, 표현, 문장 틀, 예문을 쓴다. 주제 내용의 까닭과 해석은 쓰지 않는다.
5. **보충의 범위.** 4장의 "자료에 없는 설명은 따로 둔다"를 이렇게 쓴다.
   - **채운다:** 단원이나 자료가 다룬다고 밝힌 문법의 핵심 표(규칙 활용의 모든 인칭, 다룬다고 밝힌 불규칙 동사의 활용 전체), 쓸모 있는 표현 묶음(의견, 연결어, 의문사, 시간 표현), 자주 틀리는 형태. 자료에 없어도 학생이 그 문법이나 표현을 쓰는 데 꼭 필요하면 보충 단위로 둔다.
   - **채우지 않는다:** 주제에 대한 사회적 설명, 사실, 통계.
6. **단위 쓰기.**
   - 문법 요점은 무엇에 쓰는지 → 만드는 법 → 활용이나 형태 → 예문 → 흔한 실수의 차례로 둔다.
   - 활용과 낱말 목록은 `- ` 나열로 쓰고 줄마다 하나를 둔다: `- **yo** *hablé* (I spoke)`, `- *el reciclaje* (m.) recycling`. 표는 쓰지 않는다(4장의 글 모양).
   - 목표 언어는 기울임(`*…*`)으로 쓰고 영어 뜻을 붙인다. 철자는 악센트, `ñ`, `¿`, `¡`까지 정확히 쓴다. 설명은 영어다(1장의 6).
   - 예문은 짧고 학생이 바로 쓸 만한 문장으로 쓴다. 학생이 낱말을 바꿔 끼울 수 있는 문장 틀(`*Creo que* + opinion`)을 함께 둔다.
7. **선수 개념.** 문법끼리 앞뒤가 있으면 적는다(예: 규칙 동사의 현재형 → 재귀 동사의 현재형). 낱말 세트와 표현 묶음은 대개 선수 개념이 없다.

## 11. 고른 개념 다시 정리

`input/request.md`에 "다시 정리할 개념"이 있으면, 사람이 고른 개념들을 지금 지침으로 다시 정리하는 작업이다. 고른 개념은 옛 지침으로 정리되어 모양이 맞지 않는 것이다(예: 언어 습득 과목의 주제 개념). 이 장이 앞의 장과 다르면 이 장을 따른다.

1. **재료.** 정리할 엔트리(`e01` …)는 고른 개념들이 쓴 엔트리다. 고른 개념의 원문(`input/concepts/`)과 엔트리로, 개념의 크기(3장)와 단위 쓰기(4장)를 처음부터 다시 적용한다. 언어 습득 과목이면 10장을 따른다.
2. **고른 개념마다 남기거나 없앤다.**
   - 남김: `concepts`에 그 키로 둔다. 제목을 바꾸고 단위를 고쳐 쓰고 더할 수 있다(다시 씀, 보강).
   - 없앰: `retired`에 둔다. 내용을 다른 개념으로 모두 옮겼거나(합침), 옮길 만한 내용이 없을 때다.
   - 나눔: 남기는 개념의 단위 일부를 새 개념이나 다른 개념으로 옮긴다.
3. **옛 단위의 행방을 빠짐없이 적는다.** 고른 개념의 옛 단위마다 셋 가운데 하나다.
   - 남김: 같은 개념의 `units`에 같은 `id`로 둔다.
   - 옮김: 그 내용을 담은 새 단위(`id`는 `null`)에 `"from": ["k03.u2"]`를 단다. 여러 옛 단위를 합친 단위는 모두 적는다. 일부만 옮기고 나머지는 빼는 단위도 옮김으로 적는다. 옮긴 내용은 원래 출처를 그대로 쓴다. 옮긴 단위는 `removed_units`에 다시 적지 않아도 된다.
   - 뺌: 남기는 개념이면 `removed_units`에, 없애는 개념이면 `retired[].units`에 까닭과 함께 적는다(주제의 사회적 설명, 단원 틀 같은 것).
   행방이 없는 옛 단위가 있으면 러너 검사에서 틀린다. 코멘트와 요구가 이 행방을 따라 옮겨 가기 때문이다.
4. **없애는 개념의 `into`.** 그 개념에 달린 코멘트가 따라갈 개념이다. 내용이 가장 많이 간 개념을 키(`k01`)나 `"new:<slug>"`로 적는다. 남는 개념이어야 한다.
5. **고르지 않은 개념은 보강만 한다.** 고른 개념의 내용을 받을 수 있지만(옮김), 단위를 빼거나 없애지 않는다.
6. **엔트리.** 정리할 엔트리마다 개념에 넣거나 보류한다(1장의 2). 단원 틀만 담은 엔트리는 언어 습득 과목에서 보류한다(10장의 3). `input/request.md`가 "고르지 않은 개념도 쓰는 엔트리"로 밝힌 것은 적지 않아도 된다.
7. **기록.** `out/report.md`에 고른 개념마다 무엇이 되었는지(남김, 나눔, 합침, 없앰)와 까닭을 적는다.

```json
{
  "concepts": [
    { "concept": "k01", "entries": ["e01", "e04"],
      "units": [
        { "id": "u1", "text": "…그대로이거나 고친 글…", "claims": [{ "text": "…", "src": ["20261019-5c142cdd#p2"] }] },
        { "id": null, "text": "…옮겨 온 낱말…", "from": ["k03.u2"], "claims": [{ "text": "…", "src": ["20261019-79c55c80#p4"] }] }
      ], "removed_units": [] }

  "retired": [

      "units": [{ "id": "u1", "reason": "단원 틀" }, { "id": "u3", "reason": "주제의 사회적 설명" }] }
  ],
  "held": [{ "entry": "e02", "reason": "단원 틀: 언어 습득 과목은 단원 틀을 개념으로 만들지 않는다" }]
}
```
