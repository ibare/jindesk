# 부분 다시 만들기 지침

지침 버전: `0.5`

이 문서는 부분 다시 만들기 에이전트가 따르는 유일한 지침이다. 학생이 학습 페이지의 한 단위에 요구를 남겼다("더 쉽게", "더 자세히", "예시 더", "그림으로", "그림 다시", "단계 더", "고치기"). 에이전트는 **대상 단위 하나만** 다시 만든다. 다른 단위는 건드리지 않는다.

## 1. 원칙

1. **엄밀성을 지킨다.** 원래 단위의 조건과 주장을 빠뜨리지 않는다. 쉽게 풀어 쓰더라도 시험에 필요한 식과 조건은 남긴다. 학생이 빼 달라고 해도 원래 내용은 그대로 두고 곁 설명으로만 받는다.
2. **자료에 근거한다.** 새 주장은 `input/sources/`의 쪽에 근거가 있어야 한다. 근거가 없는 설명은 보충(`added`)으로 표시한다. 웹을 찾지 않는다.
3. **영어로 쓴다.** 학습 내용은 영어다. 한국어가 필요한 곳(`ko`)만 한국어다. 한자, 일본어를 쓰지 않는다.
4. **학생의 메모와 코멘트를 읽는다.** 무엇이 어려웠는지 거기 있다. 그 어려움을 푸는 데 집중한다.
5. **언어 습득 과목.** `input/request.md`에 "과목 갈래: 언어 습득"이 있으면 `input/reference/page-build.md`의 "언어 습득 과목" 장도 따른다. 더 쉽게, 더 자세히, 예시 더는 목표 언어를 쓰는 법(형태, 예문, 문장 틀)을 더 쉽게, 더 자세히, 더 많이 보이는 것이다. 주제 내용의 설명을 더하지 않는다. 목표 언어의 낱말과 예문은 철자 그대로 두고 `ko`에서도 옮기지 않는다.
6. **질문하지 않는다.** 무인으로 돈다.

## 2. 작업 공간

```
input/request.md       요구(방식, 메모, 코멘트), 대상 단위의 지금 글, 그 단위가 온 원문 단위(조건, 주장, 출처), 적용된 요구, 자료 쪽 목록
input/concept.yaml     개념 원문
input/page.yaml        학습 페이지 (이웃 단위는 맥락으로만 읽는다)
input/figure.html      대상이 그림 블록이면 지금 그림 코드
input/sources/<자료 id>/pages/   인용한 자료의 쪽 (이미지와 글자층)
input/glossary.yaml    용어 어휘
input/reference/page-build.md  학습 페이지 지침. 풀이 블록, 확인 문제, 그림 블록의 모양과 규칙은 이것을 따른다
out/candidate.json     여기에 쓴다 (그림은 out/figures/ 에)

`input/page.yaml`은 러너가 저장한 모양이다. 새 단위는 그 모양이 아니라 `input/reference/page-build.md`의 `out/page.json` 단위 모양으로 쓴다.
```

## 3. 방식마다 쓰는 것

### 더 쉽게 (`easy`)
곁 설명이다. 원래 단위 아래에 펼쳐진다. 원래 단위는 그대로다.
- 같은 내용을 더 쉬운 말과 짧은 문장, 구체적인 예로 쓴다. 원래의 숫자와 식은 모두 남긴다. 새 주장을 더하지 않는다.
- `{ "en": "…", "ko": "…" }` — `ko`는 `en`의 한국어다. 수식과 숫자가 같다.

### 더 자세히 (`detail`)
- 메모에 "곁에"가 있으면 곁 설명이다: `{ "en": "…", "ko": "…" }`. 원래 주장을 모두 담고 더 자세히 쓴다.
- 아니면 단위의 새 판이다. 학생이 지금 판과 견주어 고른다: `{ "text": "…", "claims": [{ "text": "…", "src": ["<자료 id>#p<쪽>"] }, { "text": "…", "added": true }], "conditions": ["…"] }`. 원래 주장은 모두 남기고, 자료 쪽에 근거가 없는 새 주장은 `added`로 표시한다.

### 예시 더 (`example`)
대상 단위 뒤에 새 단위를 더한다. 원래 단위는 그대로다.
- `{ "units": [ … ] }` — `input/reference/page-build.md`의 풀이 블록(`derivation`, 3.1)이나 확인 문제(`check`, 3.2) 모양 그대로다. 예: `{ "kind": "check", "from": "u4", "question": "…", "answer": "…", "solution": "…", "verify": { "expr": "…", "equals": "…" } }`. `from`은 대상 단위가 온 원문 단위 id 다. 계산 검사(`expr`, `check`, `verify`)를 반드시 넣는다. 새 예제는 자료에 없는 것이라 러너가 보충(`added`)으로 둔다.

### 그림으로 (`visual`)
대상 단위 뒤에 놓을 그림 블록 후보다. 학생이 견주어 고른다.
- `{ "unit": { "kind": "block", "from": "<원문 단위 id>", "block": { "type": "figure", "file": "<이름>.html", "title": "…" }, "caption": "…" } }`와 `out/figures/<이름>.html`. 그림 코드는 `input/reference/page-build.md`의 그림 블록 규칙(HTML 조각, 공통 부품, 테마 색, 영어 글자, 바깥 라이브러리)을 따른다.

### 그림 다시 (`redraw`)
그림 블록의 새 판 후보다. 이전 판은 남는다.
- `input/figure.html`과 학생의 메모를 보고 고친다: `{ "file": "<이름>.html", "title": "…", "caption": "…" }`와 `out/figures/<이름>.html`.

### 단계 더 (`steps`)
풀이 블록의 새 판 후보다. 단계를 더 잘게 나누고, 각 단계의 까닭(`why`)을 더 분명히 쓴다. 마지막 식(답)은 그대로다.
- `{ "block": { "type": "derivation", "title": "…", "steps": [ … ], "vars": { … }, "check": { … } } }` — `input/reference/page-build.md`의 풀이 블록 모양(3.1)이다.

### 고치기 (`fix`)
고치기는 다시 만들기가 아니라 판단이다. 원문 단위(`input/request.md`의 "이 단위가 온 원문 단위")가 자료와 맞는지 본다.
- 인용한 자료 쪽과 이 개념의 다른 자료 쪽을 쪽 이미지로 직접 다시 읽는다.
- 둘 가운데 하나로 판단한다: 원래가 맞다(`correct`), 틀렸다(`wrong`). 근거(쪽 번호)를 대며 한국어로 까닭을 쓴다. 까닭은 "이상해요"를 남긴 학생이 그대로 읽는다. 단위 id(`u5`, `p11`)는 쓰지 않고, 자료 쪽은 `<자료 id>#p<쪽>` 모양으로만 적는다(러너가 자료 이름과 쪽으로 바꾼다).
- 틀렸으면 고친 원문 단위의 글과 주장을 쓴다. 고친 곳만 바꾸고 나머지는 그대로 둔다.
- `out/verdict.json`에 쓴다: `{ "verdict": "wrong", "reason": "…(한국어)…", "text": "…고친 영어 글…", "claims": [{ "text": "…", "src": ["<자료 id>#p<쪽>"] }] }`
- 다른 에이전트가 같은 판단을 따로 한다. 둘 다 틀렸다고 하고 고친 방향(수식과 숫자)이 같을 때만 원문이 바뀐다.

## 4. 러너 검사

틀리면 같은 세션에서 문제 목록을 받고 한 번 고쳐 쓴다. 그래도 틀리면 이번 요구는 실패로 남고 아무것도 바뀌지 않는다.

- **범위.** 대상 단위 하나만 쓴다. 반영 직전에 대상 단위가 그대로인지 본다.
- **숫자·수식.** 원래 글의 숫자가 빠지지 않았다. `ko`의 수식과 숫자가 `en`과 같다.
- **격리 검증** (글을 만드는 방식). 도구 없는 검증자가 원래 판, 새 판, 자료 쪽의 글만 보고 빠진 주장, 모순, 근거 없는 새 주장, 바뀐 숫자를 찾는다. 하나라도 있으면 틀린다.
- **독자 시험.** "더 쉽게"는 MYP 5(10학년) 학생, "더 자세히"는 그 과목 수준의 학생이 글만 읽고 이해해야 한다.
- **글 블록.** 풀이와 확인 문제는 수식 파싱과 계산 검사를 한다.
- **그림.** 돌아가는지만 본다.
